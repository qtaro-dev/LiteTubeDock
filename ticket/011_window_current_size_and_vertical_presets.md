# タスク名

チケット011 ウィンドウサイズ「現在のサイズ」反映と縦長プリセット追加

# 目的

現在、設定画面の基本設定に `ウィンドウサイズ` ドロップダウンがあり、`現在のサイズ` を選択できる。

しかし、`現在のサイズ` を選択しても、現在表示中の MainWindow の実際の幅・高さが `ウィンドウ幅` / `ウィンドウ高さ` の入力欄へ反映されない。

また、YouTubeショートのような縦長動画を小窓で表示したい場合に便利な縦長ウィンドウサイズプリセットが不足している。

そのため、以下を実装する。

- 設定画面で `現在のサイズ` を選択した時、現在表示中の MainWindow の幅・高さを取得して入力欄へ反映する
- 縦長表示向けのウィンドウサイズプリセットを追加する
- 表示メニュー側と設定画面側のプリセット候補を揃える
- 保存後に MainWindow へサイズを反映する既存動作を維持する

# 実装内容（具体的変更指示）

## 1. 作業開始前の確認

- 必ず `AGENT.md` を読むこと。
- 作業対象は `E:\Dev\LiteTubeDock` 配下のみとすること。
- `E:\Dev\LiteTubeDock` の外側にあるファイルやフォルダは一切編集しないこと。
- 既存UIの `x:Name` は原則変更しないこと。
- MainWindow、SettingsWindow、UserControl構成を壊さないこと。
- 既存の設定保存・読み込み・キャンセル・初期値リセット処理を壊さないこと。

## 2. 「現在のサイズ」選択時の反映

`GeneralSettingsView` の `WindowSizePresetComboBox` で `現在のサイズ` を選択した場合、現在表示中の MainWindow の実際の幅・高さを取得し、以下へ反映する。

- `WindowWidthTextBox`
- `WindowHeightTextBox`

期待動作:

```text
MainWindow が 1280x720 で表示されている
↓
設定画面を開く
↓
ウィンドウサイズで「現在のサイズ」を選択
↓
ウィンドウ幅 = 1280
ウィンドウ高さ = 720
```

注意:

- 実際の WPF の `Width` / `Height` と `ActualWidth` / `ActualHeight` のどちらを使うかは、既存処理と安全に整合するものを選ぶこと。
- 小数が出る場合は、整数へ丸めてよい。
- 最大化中やフルスクリーン中の場合は、安全に取得できる通常サイズを優先すること。
- 取得が難しい場合でもクラッシュしないこと。

## 3. SettingsWindowへの現在MainWindowサイズ受け渡し

`GeneralSettingsView` は UserControl に分離済みのため、現在の MainWindow サイズを受け渡す経路を用意する。

実装方針は既存構成に合わせてよい。

例:

```csharp
GeneralSettingsView.LoadSettings(AppSettings settings, double currentWindowWidth, double currentWindowHeight)
```

または

```csharp
GeneralSettingsView.SetCurrentWindowSize(double width, double height)
```

保存処理や既存の `LoadSettings` / `CollectSettings` がある場合は、それらを壊さない形で拡張すること。

## 4. 縦長プリセットを追加する

YouTubeショートや縦長動画向けに、以下の縦長サイズプリセットを追加する。

推奨プリセット:

```text
540x960
720x1280
900x1600
1080x1920
```

既存の横長プリセットは維持すること。

既存プリセット:

```text
800x600
960x540
1280x720
1600x900
1920x1080
```

## 5. 設定画面のドロップダウン候補を更新する

`WindowSizePresetComboBox` の候補を以下にする。

```text
現在のサイズ
800x600
960x540
1280x720
1600x900
1920x1080
540x960
720x1280
900x1600
1080x1920
カスタム
```

プリセットを選択した場合、`WindowWidthTextBox` / `WindowHeightTextBox` を自動更新すること。

例:

- `540x960` 選択時
  - `WindowWidthTextBox` = `540`
  - `WindowHeightTextBox` = `960`

- `720x1280` 選択時
  - `WindowWidthTextBox` = `720`
  - `WindowHeightTextBox` = `1280`

## 6. 表示メニュー側のプリセットも更新する

`MainWindow.xaml` の `表示` → `ウィンドウサイズ` サブメニューにも、縦長プリセットを追加する。

追加候補:

```text
540x960
720x1280
900x1600
1080x1920
```

推奨 `x:Name`:

- `WindowSize540x960MenuItem`
- `WindowSize720x1280MenuItem`
- `WindowSize900x1600MenuItem`
- `WindowSize1080x1920MenuItem`

既存の横長プリセットメニューは維持すること。

## 7. プリセット定義の共通化

横長・縦長プリセットの定義は、可能な範囲で定数化・共通化すること。

推奨:

- `Constants/AppConstants.cs` にプリセット名と幅・高さを定義
- 設定画面側と表示メニュー側で同じプリセット一覧を使えるようにする

ただし、過度に複雑な設計にはしないこと。

## 8. 保存処理

縦長プリセットを選択して保存した場合も、既存と同様に `settings.json` へ保存する。

例:

```json
{
  "windowSizePreset": "720x1280",
  "window": {
    "width": 720,
    "height": 1280
  }
}
```

仕様:

- `window.width` / `window.height` が正しく保存されること
- 可能であれば `windowSizePreset` に選択プリセット名も保存すること
- `現在のサイズ` 選択時は、取得した現在幅・高さを保存すること
- `現在のサイズ` のまま保存するか、`カスタム` 扱いにするかは既存設計と安全に整合する方式を選ぶこと

## 9. MainWindowへの即時反映

設定画面で縦長プリセットを選択して保存した場合、MainWindowのサイズへ即時反映する。

例:

```text
設定画面で 540x960 を選択
↓
保存
↓
MainWindow が 540x960 相当になる
```

フルスクリーン中に保存された場合は、既存仕様どおり通常表示へ戻してから反映する。

## 10. アドレスバー・お気に入りボタン・WebView2との整合性

縦長サイズにした場合でも、以下が大きく崩れないこと。

- メニュー
- アドレスバー
- WebView2表示領域
- お気に入りボタン列
- ステータスバー

ウィンドウ幅が狭くなるため、お気に入りボタン列が詰まる可能性はあるが、クラッシュしないことを優先する。

必要なら、既存のレスポンシブ/折り返し/スクロール方針を維持する。

## 11. README更新

READMEに以下を追記する。

- ウィンドウサイズプリセットに縦長サイズを追加したこと
- YouTubeショートなど縦長コンテンツ向けに利用できること
- `現在のサイズ` を選ぶと、現在表示中のウィンドウサイズが幅・高さ欄へ反映されること
- 表示メニューと設定画面の両方からサイズ変更できること

## 12. 実装しないこと

今回のタスクでは以下を実装しない。

- YouTubeショート専用モード
- 自動的な縦長判定
- 動画種別による自動サイズ変更
- DPIごとの詳細設定
- モニター選択UI
- 複数ウィンドウ対応
- フルスクリーン状態の保存
- YouTube UI改変
- Googleログイン自動化
