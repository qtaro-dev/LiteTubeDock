# チケット029: カスタムウィンドウサイズが保存後にプリセットサイズへ置き換わる不具合修正

## 目的

LiteTube Dock のプレイヤーウィンドウサイズについて、ユーザーが手動で調整した任意サイズ、または「現在のウィンドウサイズを取得」で取得したカスタムサイズが、保存後に勝手にプリセットサイズへ置き換わってしまう不具合を修正する。

ユーザーが指定したカスタムサイズは、プリセットに近いサイズへ丸めず、そのまま保存・適用・復元されるようにする。

## 前提

- 作業対象は `E:\Dev\LiteTubeDock` 配下のみとする。
- `E:\Dev\backup_LiteTubeDock` は編集しない。
- AGENT.md が存在する場合は、その内容を最優先で確認・遵守する。
- 既存設計、既存テーマ、既存ライブラリ構成を壊さない。
- 既存 `x:Name` は原則維持する。
- 今回はウィンドウサイズ保存・復元・適用処理の不具合修正のみを対象とする。
- YouTube / Google のログイン、認証情報、広告、DOM操作、WebView2まわりの処理仕様には触れない。
- YouTube広告を自動キャンセル、非表示、削除、置換、スキップする機能は実装しない。
- DOM操作、自動クリック、YouTube内部API呼び出しは行わない。

## 対象ファイル

推定対象:

- `MainWindow.xaml.cs`
- `SettingsWindow.xaml`
- `SettingsWindow.xaml.cs`
- `Views/GeneralSettingsView.xaml`
- `Views/GeneralSettingsView.xaml.cs`
- 設定モデル関連ファイル
- 設定保存・読み込みサービス関連ファイル
- ウィンドウサイズプリセット関連ファイル

## 現象

現在、以下のような不具合がある。

### 現象1: 現在サイズを取得しても、そのサイズが維持されない

例:

```text
取得したサイズ: 420 x 451
保存後のサイズ: 540 x 451
```

ユーザーは `420 x 451` を維持したいが、保存すると勝手に `540 x 451` のようなサイズへ置き換わる。

### 現象2: カスタムサイズでもプリセットに近いサイズへ強制変更される

プリセットを「カスタムサイズ」にしても、保存後に任意サイズが維持されず、一番小さいプリセットサイズ、または近いプリセットサイズへ置き換わる。

### 現象3: 手動で小さいサイズ・任意サイズにしても強制リサイズされる

ユーザーが MainWindow を手動で任意サイズに変更しても、設定保存や設定画面を閉じるタイミングで、プリセットに近いサイズへ強制的にリサイズされる。

## 期待する仕様

### 1. カスタムサイズはそのまま保存・復元する

ユーザーがカスタムサイズとして指定した値は、プリセットサイズへ丸めない。

例:

```text
420 x 451 を取得
保存
設定画面を閉じる
MainWindow は 420 x 451 のまま
アプリ再起動後も 420 x 451 で復元
```

### 2. プリセット選択時のみプリセットサイズを適用する

プリセットサイズは、ユーザーが明示的にプリセットを選択した場合のみ適用する。

例:

- 横長プリセットを選んだ場合 → 横長プリセットサイズを適用
- 縦長プリセットを選んだ場合 → 縦長プリセットサイズを適用
- カスタムサイズを選んだ場合 → 入力・取得した幅と高さをそのまま適用

### 3. カスタムサイズは最小プリセットへ置き換えない

カスタムサイズがプリセットより小さい場合でも、勝手に最小プリセットへ置き換えない。

例:

```text
420 x 451
```

が入力・取得された場合、保存後も `420 x 451` として扱う。

ただし、OSやWPFの通常制約により表示不能な極端な値を防ぐための最低限の `MinWidth` / `MinHeight` がある場合は、その制約は維持してよい。

その場合でも、アプリ独自のプリセットへ勝手に丸めないこと。

### 4. 設定画面を閉じただけで MainWindow を勝手にリサイズしない

以下の操作で MainWindow サイズが変わらないこと。

- 設定画面を開いてキャンセル
- 設定画面を右上の `×` で閉じる
- お気に入りボタンだけ変更して保存
- ヘルプ文言やその他ウィンドウサイズと無関係な設定だけ変更して保存

## 実装内容

### 1. ウィンドウサイズ保存・適用処理を調査する

以下の処理を確認する。

- 設定画面を開いた時のサイズ読み込み
- 「現在のウィンドウサイズを取得」ボタンの処理
- 「保存」ボタン押下時の処理
- 設定画面を閉じた時の処理
- アプリ終了時のウィンドウサイズ保存処理
- アプリ起動時のウィンドウサイズ復元処理
- プリセット選択時のサイズ適用処理

特に、以下のような処理がないか確認する。

```text
カスタムサイズを保存する前に、近いプリセットへ変換している
幅が最小プリセット未満なら最小プリセットへ置き換えている
設定保存時に常にプリセットサイズを再適用している
お気に入り設定保存時にもウィンドウサイズ適用処理が走っている
```

### 2. カスタムサイズ保存時は値を丸めない

カスタムサイズとして保存する場合、幅・高さの値をそのまま保存する。

例:

```text
WindowWidth = 420
WindowHeight = 451
WindowSizePreset = Custom
```

のように、カスタムであることと実サイズを矛盾なく保存する。

### 3. カスタムサイズ復元時は保存値をそのまま使う

起動時または設定保存後にカスタムサイズを適用する場合、保存済みの幅・高さをそのまま使う。

```text
Custom の場合:
保存済み Width / Height を使用

Preset の場合:
プリセット定義の Width / Height を使用
```

### 4. 設定保存時に不要なリサイズを行わない

設定画面で保存した内容がウィンドウサイズと無関係の場合、MainWindow のサイズを変更しない。

例:

- お気に入りボタンの表示名変更
- お気に入りボタンの色変更
- 太字ON/OFF
- 有効ON/OFF
- 外部遷移確認ON/OFF
- ヘルプやその他表示設定

これらの保存時に、MainWindow のサイズプリセット再適用処理が走らないようにする。

### 5. 「現在のウィンドウサイズを取得」は実サイズを正確に反映する

「現在のウィンドウサイズを取得」を押した場合、MainWindow の現在サイズを取得し、設定画面に表示する。

要件:

- 取得値が `420 x 451` なら、設定画面にも `420 x 451` と表示する。
- 保存後も `420 x 451` を維持する。
- `Custom` またはカスタム相当の状態として扱う。
- 取得後に勝手にプリセットへ変更しない。

### 6. 入力値とWPF最小サイズ制約を分けて扱う

WPFウィンドウに `MinWidth` / `MinHeight` が設定されている場合は、その制約により実際の表示サイズが変わる可能性がある。

ただし、アプリ独自のプリセット丸め処理と混同しないこと。

必要であれば以下を明確にする。

- 表示可能な最小サイズ
- プリセットサイズ
- カスタム保存サイズ

最低限の表示可能サイズを下回る値は補正してもよいが、その場合はプリセットではなく最小制約として扱う。

## 実装時の注意

- カスタムサイズをプリセットへ変換しない。
- 設定保存時に常にウィンドウサイズを再適用しない。
- お気に入り設定保存時に MainWindow サイズを変更しない。
- キャンセル時、右上 `×` で閉じた時にサイズ保存・適用が走らないようにする。
- 既存のプリセット機能自体は壊さない。
- 既存のウィンドウ位置復元機能を壊さない。
- 既存の「ウィンドウ位置・サイズを復元」設定を尊重する。
- 極端な小サイズでUIが完全に操作不能にならないよう、既存の最小サイズ制約は必要に応じて維持する。
- YouTube / Google / WebView2 関連の処理には触れない。

## 受け入れ条件（目視確認基準）

### TC-01: 現在サイズ取得後にカスタムサイズが維持される

1. LiteTube Dock を起動する。
2. MainWindow を手動で `420 x 451` 付近に調整する。
3. 設定画面を開く。
4. 基本設定で「現在のウィンドウサイズを取得」を押す。
5. 設定画面に `420 x 451` 付近の値が表示されることを確認する。
6. プリセットがカスタム相当になっていることを確認する。
7. 「保存」を押す。
8. 設定画面を閉じた直後、MainWindow が `540 x 451` などに勝手に変わらないことを確認する。
9. アプリを再起動する。
10. MainWindow が保存したカスタムサイズで復元されることを確認する。

### TC-02: カスタムサイズが最小プリセットへ置き換わらない

1. MainWindow をプリセットより小さめの任意サイズにする。
2. 設定画面を開く。
3. 「現在のウィンドウサイズを取得」を押す。
4. 「保存」を押す。
5. 保存後、最小プリセットサイズへ置き換わっていないことを確認する。

### TC-03: お気に入り設定保存でサイズが変わらない

1. MainWindow を任意サイズにする。
2. 設定画面を開く。
3. 「お気に入りボタン」を選択する。
4. 任意のスロットの表示名、色、太字などを変更する。
5. 「保存」を押す。
6. MainWindow のサイズが保存前と変わらないことを確認する。

### TC-04: キャンセルでサイズが変わらない

1. MainWindow を任意サイズにする。
2. 設定画面を開く。
3. 何か設定値を変更する。
4. 「キャンセル」を押す。
5. MainWindow のサイズが変わらないことを確認する。

### TC-05: 右上 `×` で閉じてもサイズが変わらない

1. MainWindow を任意サイズにする。
2. 設定画面を開く。
3. 何も保存せず右上 `×` で閉じる。
4. MainWindow のサイズが変わらないことを確認する。

### TC-06: プリセットを明示選択した場合はプリセットサイズになる

1. 設定画面を開く。
2. ウィンドウサイズプリセットで横長、縦長などのプリセットを明示的に選択する。
3. 「保存」を押す。
4. MainWindow が選択したプリセットサイズになることを確認する。

### TC-07: カスタムサイズ選択時は入力値を維持する

1. 設定画面を開く。
2. プリセットをカスタムサイズにする。
3. 幅・高さに任意の値を入力する。
4. 「保存」を押す。
5. 入力した幅・高さがそのまま維持されることを確認する。
6. アプリ再起動後も同じサイズで復元されることを確認する。

## 既存機能確認

- MainWindow が通常通り起動する。
- アドレスバーの URL入力・貼り付け・移動が動作する。
- 戻る、進む、再読み込み、ホームボタンが動作する。
- お気に入りボタンが動作する。
- 設定画面を開閉できる。
- ヘルプ画面、バージョン情報画面を開ける。
- ウィンドウ位置復元機能が壊れていない。
- プリセットサイズ機能が壊れていない。
- YouTube / Google / WebView2 関連の処理に変更が入っていない。

## 補足

この不具合の本質は、ユーザーが指定したカスタムサイズをアプリが勝手にプリセットへ丸めてしまうことにある。

ユーザーが手動で決めたサイズは、そのまま尊重すること。

特に以下のような置き換えは不具合として扱う。

```text
420 x 451 → 540 x 451
カスタムサイズ → 最小プリセットサイズ
任意手動サイズ → 近いプリセットサイズ
```
