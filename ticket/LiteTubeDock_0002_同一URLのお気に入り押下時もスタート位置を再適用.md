# LiteTubeDock 同一URLのお気に入り押下時もスタート位置を再適用

## 対象プロジェクト

`E:\Dev\LiteTubeDock`

※ `E:\Dev\LiteTubeDockControl` は変更しないこと。

## 現象

同じYouTube動画URLを複数のお気に入りボタンへ登録し、それぞれ異なるスタート位置を設定している場合、最初に押したボタンの位置へは移動できるが、その後に別ボタンを押してもスタート位置が適用されない。

確認例:

- 緑ボタン
  - URL: 同じYouTube動画
  - スタート位置: `00:00:54`
- 黄色ボタン
  - URL: 同じYouTube動画
  - スタート位置: `00:01:54`

現在の挙動:

1. 緑ボタンを押す
2. `00:00:54` へ移動する
3. 黄色ボタンを押す
4. 同じURLのため処理が省略され、`00:01:54` へ移動しない
5. 黄色ボタンを再度押しても、指定位置へ戻らない

## 目的

お気に入りボタンを押すたびに、そのボタンへ保存されている再生設定を必ず再適用する。

同じURL・同じ動画IDであっても、押したボタンごとに異なるスタート位置へ移動できるようにする。

## 期待する動作

- 緑ボタンを押す → `00:00:54` へ移動
- 黄色ボタンを押す → `00:01:54` へ移動
- 黄色ボタンをもう一度押す → 再び `00:01:54` へ戻る
- 緑ボタンをもう一度押す → 再び `00:00:54` へ戻る

お気に入りボタンは単なるURL移動ボタンではなく、そのボタンに保存された再生設定を毎回適用するボタンとして扱うこと。

## 実装内容

### 1. 同一URL時も処理を省略しない

お気に入りボタン押下時、現在URLと登録URLが同じという理由だけで処理を終了しないこと。

同じURLまたは同じYouTube動画IDの場合でも、以下は毎回実行する。

- スタート位置の取得
- スタート位置の範囲確認
- 指定位置へのシーク
- シーク成功確認
- 自動再生設定の適用
- ミュート設定の適用
- ループ設定の適用

### 2. 同じ動画の場合は再読み込みしない

現在表示中のYouTube動画IDと、押したお気に入りの動画IDが一致する場合は、ページ全体の再読み込みを行わず、現在の動画へ直接シークする。

処理例:

1. 押されたお気に入り設定を取得
2. 現在表示中の動画IDを取得
3. 登録動画IDと一致するか確認
4. 一致する場合はナビゲーションを省略
5. 現在の動画状態と再生可能範囲を取得
6. 毎回スタート位置へシーク
7. 自動再生・ミュート・ループを再適用

同じ動画でも現在位置と指定位置が一致している場合、シーク命令を再実行してよい。

### 3. 異なる動画の場合

現在の動画IDと登録動画IDが異なる場合は、従来どおり登録URLへ移動し、動画準備完了後にスタート位置を適用する。

既存の以下の処理を維持する。

- 動画準備待機
- 広告と本編の判定
- duration / seekable判定
- 範囲外エラー
- シーク後の実位置確認
- 多重実行キャンセル

### 4. 押下ごとに新しい要求として扱う

同じお気に入りボタンを連続して押した場合も、新しい再生要求として扱う。

- 押下ごとに新しいRequestIdを発行
- 古い待機・シーク処理はキャンセル
- 最新の押下内容を必ず優先
- 同じURLだからという理由でRequestIdを発行しない実装にしない
- 古い処理が後から再適用されないこと

### 5. 再生設定の毎回再適用

お気に入りボタンを押すたびに、以下を再適用する。

#### スタート位置

保存されている `startPositionSeconds` へ毎回移動する。

#### 自動再生

- ON: シーク成功後に再生
- OFF: シーク成功後に一時停止

#### ミュート

保存されているミュート設定を毎回適用する。

#### ループ

保存されているループ設定を毎回適用する。

前に押したお気に入りボタンの設定を引き継がないこと。

### 6. 0秒指定

スタート位置が `00:00:00` の場合も、同じ動画でボタンを押したら先頭へ戻す。

`startPositionSeconds == 0` を「何もしない」と扱わないこと。

例:

- 現在位置: `00:10:00`
- お気に入り設定: `00:00:00`
- ボタン押下結果: 動画先頭へ戻る

### 7. エラー処理

同一動画へ直接シークする場合でも、既存のエラー条件を維持する。

#### 範囲外

> 再生箇所が見つかりません。ボタンの設定を見直してください。

#### 状態取得失敗・シーク確認失敗

> 再生位置を確認できませんでした。時間をおいて再度お試しください。

同じURLで処理を省略した結果、エラーも成功確認も行われない状態を残さないこと。

### 8. ログ追加

お気に入り押下時に、以下をログへ記録する。

- RequestId
- お気に入りスロット番号
- 登録URL
- 現在URL
- 登録動画ID
- 現在動画ID
- SameUrl
- SameVideo
- NavigationSkipped
- StartPositionSeconds
- SeekRequested
- SeekVerified
- AutoPlay
- Muted
- Loop
- Result
- ErrorCode

同じURLでナビゲーションを省略し、直接シークしたことがログから分かるようにする。

## 変更しないもの

- スタート位置の入力仕様
- `HH:mm:ss` 表示
- `startPositionSeconds` の保存形式
- 数字のみ入力の変換仕様
- 動画準備待機
- 広告判定
- シーク許容誤差
- 範囲外エラー
- プレイヤーモード
- LiteTubeDockControl側のIPC仕様

## バージョン

今回はバージョン番号を変更しないこと。

`Version`、`AssemblyVersion`、`FileVersion`、`InformationalVersion` は現状維持とする。

## 受け入れ条件

1. 同じYouTube動画URLを複数のお気に入りへ登録できる
2. 各ボタンへ異なるスタート位置を設定できる
3. 緑ボタン `00:00:54` を押すと54秒付近へ移動する
4. 続けて黄色ボタン `00:01:54` を押すと1分54秒付近へ移動する
5. 黄色ボタンを再度押すと、再び1分54秒付近へ戻る
6. 緑ボタンを再度押すと、再び54秒付近へ戻る
7. 同じ動画の場合はページ全体を再読み込みしない
8. 同じURLでもスタート位置適用処理を省略しない
9. `00:00:00` のボタンを押すと動画先頭へ戻る
10. 自動再生・ミュート・ループが押下ごとに再適用される
11. 連続押下時は最新のボタン設定が優先される
12. 古いシーク処理が後から誤適用されない
13. 異なる動画URLの場合は従来どおり移動後にスタート位置が適用される
14. Debug / Releaseビルドが警告0・エラー0で成功する
15. LiteTubeDockControl側に変更が入っていない
16. バージョン番号が変更されていない

## 確認手順

### 同じ動画・異なる位置

1. 同じYouTube動画をお気に入り01と02へ登録する
2. お気に入り01のスタート位置を `00:00:54` に設定する
3. お気に入り02のスタート位置を `00:01:54` に設定する
4. 両方を保存する
5. お気に入り01を押す
6. 54秒付近へ移動することを確認する
7. お気に入り02を押す
8. 1分54秒付近へ移動することを確認する
9. お気に入り02を再度押す
10. 再び1分54秒付近へ戻ることを確認する
11. お気に入り01を押す
12. 再び54秒付近へ戻ることを確認する

### 0秒へ戻す

1. 同じ動画を別のお気に入りへ登録する
2. スタート位置を `00:00:00` にする
3. 動画を数分進める
4. `00:00:00` のお気に入りボタンを押す
5. 動画先頭へ戻ることを確認する

### 設定の再適用

1. 同じ動画を2つのお気に入りへ登録する
2. 一方を自動再生ON・ミュートOFF・ループOFFにする
3. もう一方を自動再生OFF・ミュートON・ループONにする
4. 交互に押す
5. 押したボタンの設定へ毎回切り替わることを確認する

### 異なる動画

1. 別のYouTube動画を登録したお気に入りを押す
2. URLが切り替わることを確認する
3. 動画準備後に指定スタート位置へ移動することを確認する
