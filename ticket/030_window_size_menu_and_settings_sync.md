# チケット030: 表示メニューのウィンドウサイズと設定画面のサイズ設定を同期する

## 目的

MainWindow の `表示` → `ウィンドウサイズ` から選ぶサイズ設定と、設定画面の基本設定で扱っているウィンドウサイズ設定がリンクされていない。

そのため、メニュー側でサイズを変更しても設定画面側に反映されない、または設定画面側で保存した内容とメニュー側の状態が一致しない可能性がある。

ウィンドウサイズに関する操作元を統一し、どこから変更しても同じ設定値として扱われるようにする。

## 前提

- 作業対象は `E:\Dev\LiteTubeDock` 配下のみとする。
- `E:\Dev\backup_LiteTubeDock` は編集しない。
- AGENT.md が存在する場合は、その内容を最優先で確認・遵守する。
- 既存設計、既存テーマ、既存ライブラリ構成を壊さない。
- 既存 `x:Name` は原則維持する。
- 今回はウィンドウサイズ設定の同期・一元化のみを対象とする。
- チケット029の「カスタムサイズがプリセットへ勝手に置き換わる不具合修正」と矛盾しないようにする。
- YouTube / Google のログイン、認証情報、広告、DOM操作、WebView2まわりの処理仕様には触れない。
- YouTube広告を自動キャンセル、非表示、削除、置換、スキップする機能は実装しない。
- DOM操作、自動クリック、YouTube内部API呼び出しは行わない。

## 現状の課題

### 課題1: 表示メニュー側と設定画面側がリンクしていない

`表示` → `ウィンドウサイズ` の操作と、設定画面の基本設定にあるウィンドウサイズ設定が、同じ設定値として連動していない。

例:

- 表示メニューで「横長」を選んでも、設定画面側のプリセット表示が変わらない
- 設定画面で「カスタムサイズ」を保存しても、表示メニュー側の状態と一致しない
- 現在どのサイズ設定が有効なのか分かりづらい

### 課題2: サイズ変更の入口が複数あり、挙動がバラつく

ウィンドウサイズを変更できる入口が複数ある。

- 表示メニュー
- 設定画面のウィンドウサイズプリセット
- 現在のウィンドウサイズを取得
- 手動リサイズ

これらがそれぞれ別々の処理を持っていると、保存値や復元値がずれやすい。

## 期待する仕様

### 1. 表示メニューと設定画面は同じ設定値を参照する

`表示` → `ウィンドウサイズ` と、設定画面のウィンドウサイズ設定は、同じ設定モデル・同じ保存値を参照する。

期待:

- 表示メニューでサイズを選ぶ
- 設定画面を開く
- 設定画面側にも選択したサイズ設定が反映されている

逆方向も同じ。

- 設定画面でサイズ設定を変更して保存する
- 表示メニュー側の状態も、保存したサイズ設定と一致する

### 2. 表示メニューでプリセットを選んだ場合

表示メニューからプリセットサイズを選んだ場合は、以下を行う。

- MainWindow をそのプリセットサイズへ変更する
- 設定値にも選択したプリセットを保存または反映する
- 設定画面を開いた時、そのプリセットが選ばれている状態にする

例:

```text
表示 → ウィンドウサイズ → 横長
```

を選んだ場合:

```text
MainWindow が横長サイズになる
設定画面のプリセットも「横長」になる
```

### 3. 設定画面でプリセットを選んだ場合

設定画面でプリセットサイズを選び保存した場合は、以下を行う。

- MainWindow をそのプリセットサイズへ変更する
- 表示メニュー側も、そのプリセットが有効な状態として扱う
- アプリ再起動後も同じプリセットが復元される

### 4. カスタムサイズの場合

カスタムサイズの場合は、チケット029の方針を優先する。

要件:

- カスタムサイズをプリセットへ勝手に丸めない
- 入力または取得した幅・高さをそのまま使う
- 表示メニュー側では、カスタムサイズであることが分かる状態にする

表示メニュー側にカスタム項目がある場合:

```text
表示 → ウィンドウサイズ → カスタム
```

をチェック状態にする。

カスタム項目がない場合は、無理に追加しなくてもよいが、既存プリセットのどれかが誤って選択状態にならないようにする。

### 5. 手動リサイズした場合の扱い

ユーザーが MainWindow を手動でリサイズした場合、勝手にプリセットへ丸めない。

手動リサイズ後の扱いは、既存設計に合わせてよいが、以下を満たすこと。

- 手動サイズが保存対象になる場合は、カスタムサイズとして扱う
- 手動サイズが即時保存対象ではない場合でも、設定画面の「現在のウィンドウサイズを取得」で取得した値はカスタムとして保存できる
- 手動リサイズ直後に表示メニューや設定画面が誤ったプリセット状態にならない

## 実装内容

### 1. ウィンドウサイズ設定の参照元を確認する

以下が別々の値を持っていないか確認する。

- 表示メニューのサイズ選択処理
- 設定画面のプリセット選択処理
- 設定保存値
- 起動時復元処理
- 現在サイズ取得処理

必要であれば、ウィンドウサイズ設定を共通のモデル・共通メソッドへ寄せる。

### 2. 表示メニューのサイズ変更処理を設定画面側と共通化する

表示メニューでサイズを選択した場合も、設定画面と同じルールでサイズ設定を扱う。

推奨:

```text
ApplyWindowSizePreset(preset)
SaveWindowSizeSetting(preset, width, height)
UpdateWindowSizeMenuState()
```

のように、役割を分けて整理する。

### 3. 設定画面保存後に表示メニュー状態を更新する

設定画面でウィンドウサイズ設定を保存した後、MainWindow側の表示メニュー状態も更新する。

例:

- 横長保存 → 表示メニューの横長が選択状態
- 縦長保存 → 表示メニューの縦長が選択状態
- カスタム保存 → 表示メニューのカスタムが選択状態、またはプリセット未選択状態

### 4. 表示メニュー選択後に設定値を保存・反映する

表示メニューでプリセットを選んだ場合、MainWindowのサイズを変えるだけでなく、設定値にも反映する。

要件:

- アプリ再起動後も、表示メニューで選んだサイズが復元される
- 設定画面を開いた時も、そのサイズ設定が表示される

### 5. カスタムサイズはプリセットへ丸めない

チケット029と同じく、カスタムサイズはそのまま保持する。

以下のような変換は禁止する。

```text
420 x 451 → 540 x 451
カスタムサイズ → 最小プリセット
任意手動サイズ → 近いプリセット
```

### 6. メニューのチェック状態を整理する

表示メニューにチェック状態がある場合、現在のサイズ設定に合わせて更新する。

要件:

- 現在選択中のプリセットだけチェックされる
- カスタム時に別プリセットが誤ってチェックされない
- 設定画面保存後もメニュー表示が古い状態のまま残らない

## 実装時の注意

- チケット029の不具合修正と矛盾しないこと。
- カスタムサイズをプリセットへ強制変換しないこと。
- 表示メニューを押しただけで、設定画面側と異なる別管理値を作らないこと。
- お気に入り設定保存時に、不要なウィンドウサイズ再適用をしないこと。
- 設定画面をキャンセルした場合、表示メニュー側のサイズ設定も変更しないこと。
- 設定画面を右上 `×` で閉じた場合、サイズ設定を勝手に変更しないこと。
- MainWindow の通常リサイズ操作を壊さないこと。
- YouTube / Google / WebView2 関連の処理には触れない。

## 受け入れ条件（目視確認基準）

### TC-01: 表示メニューで横長を選ぶと設定画面にも反映される

1. LiteTube Dock を起動する。
2. `表示` → `ウィンドウサイズ` → `横長` を選択する。
3. MainWindow が横長サイズになることを確認する。
4. 設定画面を開く。
5. 基本設定のウィンドウサイズ設定が「横長」になっていることを確認する。

### TC-02: 表示メニューで縦長を選ぶと設定画面にも反映される

1. `表示` → `ウィンドウサイズ` → `縦長` を選択する。
2. MainWindow が縦長サイズになることを確認する。
3. 設定画面を開く。
4. 基本設定のウィンドウサイズ設定が「縦長」になっていることを確認する。

### TC-03: 設定画面でプリセット変更すると表示メニューにも反映される

1. 設定画面を開く。
2. 基本設定でウィンドウサイズプリセットを変更する。
3. 「保存」を押す。
4. `表示` → `ウィンドウサイズ` を開く。
5. 保存したプリセットが現在のサイズ設定として扱われていることを確認する。

### TC-04: 表示メニューで選んだサイズが再起動後も復元される

1. `表示` → `ウィンドウサイズ` から任意のプリセットを選ぶ。
2. アプリを終了する。
3. アプリを再起動する。
4. 選んだサイズで復元されることを確認する。
5. 設定画面を開き、同じサイズ設定が表示されることを確認する。

### TC-05: カスタムサイズは表示メニュー操作後も丸められない

1. MainWindow を手動で `420 x 451` 付近に調整する。
2. 設定画面を開く。
3. 「現在のウィンドウサイズを取得」を押す。
4. カスタムサイズとして保存する。
5. 設定画面を閉じる。
6. `表示` → `ウィンドウサイズ` を開く。
7. 既存プリセットのどれかが誤って選択状態になっていないことを確認する。
8. MainWindow が `540 x 451` などへ勝手に変更されていないことを確認する。

### TC-06: お気に入り設定保存では表示メニューサイズ状態が変わらない

1. 表示メニューまたは設定画面で任意のウィンドウサイズ設定にする。
2. 設定画面を開く。
3. 「お気に入りボタン」を選択する。
4. 表示名や色など、ウィンドウサイズと無関係な設定を変更する。
5. 「保存」を押す。
6. MainWindow のサイズが変わらないことを確認する。
7. 表示メニューのウィンドウサイズ状態も変わらないことを確認する。

### TC-07: キャンセルでは同期状態が変わらない

1. 設定画面を開く。
2. ウィンドウサイズ設定を一時的に変更する。
3. 「キャンセル」を押す。
4. MainWindow のサイズが変わらないことを確認する。
5. 表示メニューの状態も変更前のままであることを確認する。

## 既存機能確認

- MainWindow が通常通り起動する。
- アドレスバーの URL入力・貼り付け・移動が動作する。
- 戻る、進む、再読み込み、ホームボタンが動作する。
- お気に入りボタンが動作する。
- 設定画面を開閉できる。
- ヘルプ画面、バージョン情報画面を開ける。
- ウィンドウ位置復元機能が壊れていない。
- チケット029のカスタムサイズ保持仕様が壊れていない。
- YouTube / Google / WebView2 関連の処理に変更が入っていない。

## 補足

このチケットの本質は、ウィンドウサイズに関する入口を一元化することである。

ユーザーから見ると、以下は同じ「ウィンドウサイズ設定」である。

- 表示メニューのウィンドウサイズ
- 設定画面のウィンドウサイズプリセット
- 現在のウィンドウサイズ取得
- カスタムサイズ保存

これらが別々に動くと混乱するため、同じ設定値として扱うこと。
