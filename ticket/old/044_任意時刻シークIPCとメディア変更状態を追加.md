# チケット044：任意時刻シークIPCとメディア変更状態を追加

## 対象プロジェクト

`E:\Dev\LiteTubeDock`

## 背景

LiteTubeDockControlのミキサーへ、各プレイヤーの現在再生時間表示と、指定したタイムスタンプ位置から再生する機能を追加する。

現在は `seek-to-start` しかなく、任意時刻へ移動するIPCがない。また、Control側の時計だけで再生時間を加算すると、一時停止・バッファリング・手動シーク・広告・再生速度変更・別動画への遷移などで実再生位置とずれる。

## 目的

任意の再生位置へ移動するIPCを追加する。

現在再生時間、動画長、シーク可否、ライブ判定、メディア変更識別情報を返し、Control側のタイムスタンプUIと確実に同期できるようにする。

## 対象ファイル（推定可）

- `Models/IpcCommand.cs`
- `Models/IpcResponse.cs`
- `Models/IpcStatusData.cs`
- `Models/IpcAudioStatusData.cs`
- IPC受信・実行サービス
- WebView2内メディア操作スクリプト
- `Constants/AppConstants.cs`
- `LiteTubeDock.csproj`
- 必要に応じて新規モデル
- `docs/ipc_commands.md`

## 実装内容

### 1. `seek-to` IPCを追加

任意の再生位置へ移動するIPCコマンドを追加する。

コマンド名：

`seek-to`

送信パラメータ：

`positionSeconds`

型：

- 数値
- 0以上
- 小数対応

例：

```json
{
  "command": "seek-to",
  "positionSeconds": 90.5
}
```

### 2. 入力検証

以下を拒否する。

- パラメータなし
- null
- 非数値
- NaN
- Infinity
- 負数
- 動画長を超える値
- 極端に大きな値

動画長を超える場合は `POSITION_OUT_OF_RANGE` を返す。

### 3. シーク対象

WebView2内の再生対象video/audio要素を特定し、対象メディアの `currentTime` を変更する。

複数要素がある場合は、現在再生中または主再生対象として判定した要素を優先する。

対象が見つからない場合は異常終了せず、明確なErrorCodeを返す。

### 4. 成功応答

成功時に最低限、以下を返す。

- `success`
- `requestedPositionSeconds`
- `actualPositionSeconds`
- `duration`
- `isSeekable`
- `isLive`
- `currentUrl`
- `mediaTitle`
- `mediaIdentity`
- `message`

### 5. ErrorCode

最低限、以下を用意する。

- `INVALID_PARAMETER`
- `MEDIA_NOT_FOUND`
- `MEDIA_NOT_READY`
- `SEEK_NOT_SUPPORTED`
- `POSITION_OUT_OF_RANGE`
- `WEBVIEW_NOT_READY`
- `SCRIPT_EXECUTION_FAILED`
- `TIMEOUT`
- `UNKNOWN_ERROR`

既存の命名規則がある場合はそれに合わせる。

### 6. ライブ・シーク不能メディア

ライブ配信やシーク不能メディアでは、無理にcurrentTimeを書き換えない。

以下を返す。

- `isSeekable=false`
- `isLive`
- 適切なErrorCode
- ユーザー向けmessage

### 7. `get-audio-status` を拡張

既存フィールドと重複しないよう確認し、最低限、以下を返す。

- `currentTime`
- `currentTimeSeconds`
- `duration`
- `durationSeconds`
- `isSeekable`
- `isLive`
- `playbackRate`
- `isPlaying`
- `isPaused`
- `currentUrl`
- `mediaTitle`
- `mediaIdentity`
- `mediaRevision`
- `mediaElementCount`

### 8. メディア変更識別

動画変更をControl側で判定できるよう、安定した `mediaIdentity` または世代番号 `mediaRevision` を返す。

判定材料候補：

- currentSrc
- src
- 現在URL
- media title
- duration
- YouTube動画ID
- video/audio要素差し替え

YouTube限定実装にせず、任意URLのvideo/audio要素でも扱える構成にする。

### 9. 動画変更監視

以下の変化を監視する。

- `currentSrc` 変更
- `src` 変更
- URL変更
- media title変更
- duration変更
- video/audio要素差し替え
- `loadedmetadata`
- `durationchange`
- `emptied`

新しいメディアになった場合、Control側が `0:00:00` へ戻せる識別情報を返す。

### 10. 再生時間の取得

`currentTime` は実際のメディア要素から取得する。

Control側で独自加算する前提にしない。

小数秒まで取得可能にし、表示側で整数秒へ丸められるようにする。

### 11. `seek-to` は再生を強制しない

役割を分離する。

- `seek-to`：位置移動
- `play`：再生開始
- `pause`：一時停止

Control側は、指定時刻再生時に `seek-to` 成功後に `play` を送信する。

### 12. シーク完了確認

`currentTime` 代入直後だけで成功判定しない。

必要に応じて以下を監視する。

- `seeking`
- `seeked`
- currentTime反映
- タイムアウト

一定時間内に反映しない場合は `TIMEOUT` を返す。

### 13. 広告・メディア差し替え耐性

広告、動画切替、メディア要素差し替え時でもLiteTubeDockを異常終了させない。

主メディアを特定できない場合はErrorCodeとmessageを返す。

広告スキップ・非表示・自動回避は実装しない。

### 14. IPCログ

以下を記録する。

- command
- requestedPositionSeconds
- actualPositionSeconds
- duration
- isSeekable
- isLive
- mediaIdentity
- currentUrl
- result
- errorCode
- durationMs

定期取得成功ログは大量出力しない。

### 15. IPC仕様書

`docs/ipc_commands.md` を更新する。存在しない場合は新規作成してよい。

記載内容：

- `seek-to`
- パラメータ
- 成功応答
- ErrorCode
- `get-audio-status` の追加項目
- Control側利用予定

### 16. 既存IPCを壊さない

以下を維持する。

- `play`
- `pause`
- `seek-to-start`
- `get-audio-status`
- `set-volume`
- `set-muted`
- `get-status`
- ミュート継続

### 17. バージョン確認

実装完了時に以下を一致させる。

- `Constants/AppConstants.cs`
  - `AppVersion`
- `LiteTubeDock.csproj`
  - `Version`
  - `AssemblyVersion`

  - `InformationalVersion`

- exeのファイルバージョン
- dllのファイルバージョン

### 18. ビルド成果物

更新時はexeだけを差し替えない。

以下を同一ビルド成果物で統一する。

- exe
- dll
- deps.json
- runtimeconfig.json
- その他依存ファイル

## 受け入れ条件（目視確認基準）

1. `seek-to` へ90秒を送信すると、対象動画が90秒付近へ移動する。
2. `seek-to` へ90.5秒を送信すると、小数秒指定が処理される。
3. 成功応答にrequestedとactualが含まれる。
4. `seek-to` 単体では再生状態を勝手に変更しない。
5. `seek-to` 成功後に `play` を送ると指定位置から再生する。
6. 負数・非数値・パラメータなしで明確なErrorCodeが返る。
7. duration超過値で異常終了しない。
8. メディア未検出時に `MEDIA_NOT_FOUND` 等が返る。
9. ライブ・シーク不能動画で `isSeekable=false` が返る。
10. `get-audio-status` で実currentTimeが取得できる。
11. 一時停止中はcurrentTimeが不自然に増え続けない。
12. YouTube側で手動シークすると次回取得値へ反映される。
13. 動画変更時にmediaIdentityまたはmediaRevisionが変わる。
14. 広告や動画要素差し替え時にアプリが落ちない。
15. Debugビルドが警告0・エラー0で成功する。
16. Releaseビルドが警告0・エラー0で成功する。
17. アプリ内表示、csproj、exe、dllのバージョン定義が一致する。
