# タスク名

チケット005fix1 ウィンドウサイズプリセット未実装対応とウィンドウ位置リセット追加

# 目的

チケット005で予定していたウィンドウサイズプリセットのうち、設定画面のウィンドウ幅・高さ入力欄は追加済みだが、表示メニュー配下から選べるサイズプリセットが未実装である。

また、マルチディスプレイ環境では、保存されたウィンドウ位置が存在しない画面側に残り、アプリが画面外に表示される可能性がある。

そのため、以下を実装する。

- 表示メニューからウィンドウサイズプリセットを選べるようにする
- 表示メニューからウィンドウ位置をメインディスプレイ左上付近へリセットできるようにする
- 起動時に保存済みウィンドウ位置が画面外の場合、自動的に安全な位置へ戻す
- 設定画面のウィンドウ幅・高さ入力欄を、数字入力に適した幅へ調整する

# 実装内容（具体的変更指示）

## 1. 作業開始前の確認

- 必ず `AGENT.md` を読むこと。
- 作業対象は `E:\Dev\LiteTubeDock` 配下のみとすること。
- `E:\Dev\LiteTubeDock` の外側にあるファイルやフォルダは一切編集しないこと。
- 既存UIの `x:Name` は原則変更しないこと。
- 既存のMainWindow、SettingsWindowのレイアウトを全面的に作り直さないこと。

## 2. 表示メニューにウィンドウサイズプリセットを追加する

`MainWindow.xaml` の `ViewMenuItem` 配下に、ウィンドウサイズ用のサブメニューを追加する。

推奨構成:

```text
表示
├─ 常に最前面
├─ 戻る
├─ 進む
├─ 再読み込み
├─ ホーム
├─ ウィンドウサイズ
│  ├─ 800x600
│  ├─ 960x540
│  ├─ 1280x720
│  ├─ 1600x900
│  └─ 1920x1080
└─ ウィンドウ位置をリセット
```

推奨 `x:Name`:

- `WindowSizeMenuItem`
- `WindowSize800x600MenuItem`
- `WindowSize960x540MenuItem`
- `WindowSize1280x720MenuItem`
- `WindowSize1600x900MenuItem`
- `WindowSize1920x1080MenuItem`
- `ResetWindowPositionMenuItem`

既存のメニュー項目名は変更しないこと。

## 3. プリセット選択時の動作

各サイズプリセットをクリックしたら、MainWindowのサイズを即時変更する。

- `800x600`
- `960x540`
- `1280x720`
- `1600x900`
- `1920x1080`

仕様:

- ウィンドウが通常表示の場合は、そのまま幅・高さを変更する
- フルスクリーン中は、サイズ変更を行わない、または通常表示へ戻してから変更する
- どちらにするかは既存実装と競合しない安全な方式を選ぶこと
- サイズ変更後、ステータスバーに変更完了が分かるメッセージを表示してよい
- 終了時には既存の保存処理でサイズが保存されること

## 4. ウィンドウ位置リセットを追加する

`ResetWindowPositionMenuItem` をクリックしたら、MainWindowをメインディスプレイ左上付近へ移動する。

初期位置:

```text
Left = 100
Top = 100
```

仕様:

- メインディスプレイの作業領域を基準にする
- タスクバーに重なりにくい位置へ移動する
- 位置リセット後、必要に応じて `settings.json` にも反映されること
- ステータスバーに「ウィンドウ位置をリセットしました」などの表示をしてよい

## 5. 起動時の画面外チェックを追加する

アプリ起動時に、保存済みのウィンドウ位置が現在接続されているディスプレイ範囲外かどうかを判定する。

画面外と判断する例:

- 保存された `Left` / `Top` が、現在接続されているどのディスプレイの作業領域にも入っていない
- マルチディスプレイ構成変更により、保存位置が存在しない画面側になっている

画面外の場合:

- メインディスプレイ左上付近へ移動する
- 基準は `Left = 100`、`Top = 100`
- アプリが見えない位置で起動しないようにする

注意:

- 判定は厳密すぎなくてよい
- 最低限、ウィンドウの左上座標がどの画面にも入っていない場合はリセットすること
- 最大化・最小化・フルスクリーン状態の復元と競合しないようにすること

## 6. 設定画面のウィンドウ幅・高さ入力欄を調整する

現在、設定画面の `ウィンドウ幅` / `ウィンドウ高さ` の入力欄が数字入力欄としては長めである。

以下のように調整する。

- 入力欄の幅を80〜100px程度にする
- ラベルと入力欄の間隔を見やすくする
- 既存の左カテゴリ型レイアウトは維持する
- `SettingsWindow.xaml` の全面再設計はしない

対象UI名が存在する場合は維持すること。

推奨名:

- `WindowWidthTextBox`
- `WindowHeightTextBox`

READMEに以下を追記する。

# 受け入れ条件（目視確認基準）

## ビルド確認

- `dotnet build` でビルドエラーがない
- 警告が出る場合は内容を報告すること
- アプリ起動時にクラッシュしない

## 表示メニュー確認

- `表示` メニュー配下に `ウィンドウサイズ` サブメニューが表示される
- `800x600` が選択できる
- `960x540` が選択できる
- `1280x720` が選択できる
- `1600x900` が選択できる
- `1920x1080` が選択できる
- `表示` メニュー配下に `ウィンドウ位置をリセット` が表示される

## サイズ変更確認

- `800x600` を選ぶと、MainWindowが800x600相当になる
- `960x540` を選ぶと、MainWindowが960x540相当になる
- `1280x720` を選ぶと、MainWindowが1280x720相当になる
- サイズ変更後もWebView2、ボタン列、ステータスバーが大きく崩れない
- アプリ再起動後、最後に保存されたサイズが復元される

## ウィンドウ位置リセット確認

- MainWindowを任意の位置へ移動する
- `表示` → `ウィンドウ位置をリセット` を押す
- MainWindowがメインディスプレイ左上付近へ移動する
- アプリがクラッシュしない

## 画面外復旧確認

可能であれば、以下を確認する。

- `settings.json` のウィンドウ位置を画面外相当の値にした状態で起動する
- MainWindowが画面外ではなく、メインディスプレイ左上付近に表示される

手動確認が難しい場合は、実装内容として画面外判定処理が入っていることを報告すること。

## 設定画面確認

- `設定` → `設定を開く` で設定画面が開く
- 基本設定画面の `ウィンドウ幅` / `ウィンドウ高さ` 入力欄が数字入力に適した短めの幅になっている
- レイアウトが大きく崩れていない

## 既存機能確認

- Home / Back / Forward / Reload が動作する
- お気に入りボタンでURL遷移できる
- フルスクリーン切り替えが壊れていない
- 設定保存が壊れていない
- YouTubeログイン情報、Google ID、パスワード、認証トークンは保存されていない
