# タスク名

040：プレイヤーモード時の白い外枠・角丸・非クライアント境界を非表示にする

# 目的

LiteTubeDockを `--player-mode` で起動し、LiteTubeDockControlから2×2、3×3、4×4などに配置した際、タイトルバーは非表示になったが、各プレイヤーの外周に白い線と角丸が残っている。

この白い線はウィンドウ間隔ではなく、LiteTubeDockプレイヤー本体側のWindows非クライアント領域、DWM境界、リサイズ枠、角丸、またはルート要素のBorder等によって描画されている可能性がある。

LiteTubeDock本体側で原因を特定し、`--player-mode` のときだけ白い外枠・角丸・境界線を完全に非表示にする。

通常モードでは、現在の標準ウィンドウ表示を維持する。

- ウィンドウ移動・リサイズのヒットテスト処理を実装しているファイル
- 診断ログを出力しているファイル

# 実装内容（具体的変更指示）

1. LiteTubeDock本体だけを修正すること。

2. LiteTubeDockControl側のレイアウト計算、ウィンドウ間隔、外周余白、配置処理は変更しないこと。

3. 現在の `--player-mode` 実装を確認し、以下のどれが白い外枠・角丸の原因になっているかを特定すること。

   - Windows 11のDWM境界線
   - Windows 11の角丸
   - `ResizeMode=CanResize` による非クライアント境界
   - `WindowChrome.ResizeBorderThickness`
   - `WindowChrome.CornerRadius`
   - `WindowChrome.GlassFrameThickness`
   - `WindowStyle=None` 適用後に残るWin32スタイル
   - `WS_THICKFRAME`
   - `WS_BORDER`
   - `WS_DLGFRAME`
   - `WS_CAPTION`
   - `WS_EX_CLIENTEDGE`
   - `WS_EX_WINDOWEDGE`
   - XAML上のルートBorder
   - ルートGridまたはWebView2外周のMargin/Padding
   - フルスクリーン解除後に再適用されるウィンドウ属性
   - DWMによる自動枠色

4. `--player-mode` のときだけ、各LiteTubeDock外周の白い線を表示しないこと。

5. `--player-mode` のときだけ、Windows 11の角丸を無効化し、四隅を直角にすること。

6. DWMのウィンドウ境界線色を透明化または非表示化できる場合は、プレイヤーモード時に適用すること。

7. 必要に応じて以下のDWM属性を使用し、現在のWindowsバージョンで利用可能か確認してから適用すること。

   - ウィンドウ角丸設定
   - 境界線色
   - キャプション色
   - テキスト色
   - 非クライアント描画制御

8. 対応していないWindowsバージョンやAPI呼び出し失敗時は、アプリを異常終了させず、安全にフォールバックすること。

9. `WindowStyle=None`、Win32スタイル変更、DWM属性変更後に、必要なフレーム再計算を行うこと。

10. フレーム再計算後に、実際のウィンドウ外周へ白線が残っていないことを目視で確認できる状態にすること。

11. 既存のタイトルバー非表示処理を維持すること。

12. プレイヤーモード時に以下を表示しないこと。

   - Windows標準タイトルバー
   - アプリアイコン
   - タイトル文字
   - 最小化ボタン
   - 最大化ボタン
   - 閉じるボタン
   - 白い外枠
   - 角丸
   - リサイズ枠として見える白い線

13. タイトルバーと外枠を消した後も、既存のウィンドウ移動機能を維持すること。

   - 上端約6pxのドラッグ
   - Alt+ドラッグ

14. タイトルバーと外枠を消した後も、既存のリサイズ機能を維持すること。

   - 左右端
   - 上下端
   - 四隅

15. 標準の非クライアントリサイズ枠を非表示にする必要がある場合は、既存の独自ヒットテストまたはWin32ヒットテスト処理でリサイズを維持すること。

16. リサイズ操作のためだけに白い境界線を表示しないこと。

17. `--player-mode` ではない通常モードでは、現在のタイトルバー・角丸・外枠・標準操作を維持すること。

18. フルスクリーンへ切り替え、解除した後も、白い外枠・角丸・タイトルバーが復活しないこと。

19. ウィンドウサイズ変更、モニター移動、DPI変更後も、白い外枠や角丸が再表示されないこと。

20. 2×2、3×3、4×4、横並び、縦並び、自由配置のどの配置でも同じ外観になること。

21. プレイヤー数や配置種類を外枠非表示の条件にしないこと。

22. 1台だけを `--player-mode` で起動した場合でも、外枠・角丸を非表示にすること。

23. WebView2の動画表示領域へ不要なMargin、Padding、BorderThicknessを追加しないこと。

24. 白線除去のために動画領域を切り取ったり、拡大表示して内容を欠けさせたりしないこと。

25. YouTube通常動画、ライブ、ShortsのURL、再生位置、再生状態、ミュート状態へ影響を与えないこと。

26. 既存のShortsリサイズ再描画対策を破壊しないこと。

27. 既存のIPCコマンドを破壊しないこと。

28. 診断ログへ、最低限以下を記録すること。

   - PlayerMode
   - WindowStyle
   - ResizeMode
   - WindowChromeの有無
   - 適用前Win32Style
   - 適用後Win32Style
   - 適用前Win32ExStyle
   - 適用後Win32ExStyle
   - DWM角丸設定結果
   - DWM境界線色設定結果
   - フレーム再計算結果
   - BorderlessFrameApplied
   - フルスクリーン解除後の再適用結果

29. `BorderlessFrameApplied=True` は、処理を呼び出しただけではなく、外枠・角丸・対象スタイルが実際に除去されたことを確認できた場合だけ記録すること。

30. Debugビルドを実行し、警告0・エラー0を確認すること。

# 受け入れ条件（目視確認基準）

## 目視確認前提

- LiteTubeDockの修正版一式を新しい出力フォルダーへ完全に発行またはコピーする
- exeだけでなく、同時に生成されたdll、deps.json、runtimeconfig.json等を同じビルド成果物で統一する
- 古いファイルと新しいファイルを混在させない
- 既存のLiteTubeDockプロセスをすべて終了する
- LiteTubeDockControlから参照する実行ファイルパスを修正版へ設定する
- Controlから `--player-mode` 付きでLiteTubeDockを起動する

## 1台起動確認

1. テスターがControlからLiteTubeDockを1台起動する。
2. 配置操作を行う前の状態を確認する。
3. Windows標準タイトルバーが表示されないこと。
4. ウィンドウ外周に白い線が表示されないこと。
5. 四隅が丸くならず直角であること。
6. 動画表示領域がウィンドウ端まで表示されること。
7. 動画内容が切れたり、不自然に拡大されたりしていないこと。

## 2×2確認

1. テスターがLiteTubeDockを4台起動する。
2. Controlで外周余白 `0`、ウィンドウ間隔 `0` にする。
3. 2×2配置を適用する。
4. 各Dockの上端・下端・左端・右端に白い外枠が表示されないこと。
5. 中央の縦線が白いウィンドウ枠によって表示されないこと。
6. 中央の横線が白いウィンドウ枠によって表示されないこと。
7. 4画面中央に白い十字状の境界が残らないこと。
8. 四隅の角丸による白い欠けが表示されないこと。

## 3×3確認

1. テスターがLiteTubeDockを9台起動する。
2. 3×3配置を適用する。
3. すべての内部境界で白い外枠が表示されないこと。
4. 一部のDockだけ外枠や角丸が復活していないこと。

## 4×4確認

1. テスターがLiteTubeDockを16台起動する。
2. 4×4配置を適用する。
3. すべてのDockで外枠と角丸が非表示であること。
4. 画面数が増えても白線が再発しないこと。

## 移動確認

1. テスターが上端約6pxをドラッグする。
2. ウィンドウを移動できること。
3. テスターがAlt+ドラッグを行う。
4. ウィンドウを移動できること。

## リサイズ確認

1. テスターが左端、右端、上端、下端をドラッグする。
2. 各方向へリサイズできること。
3. テスターが四隅をドラッグする。
4. 斜め方向へリサイズできること。
5. リサイズ操作中および完了後も白い外枠が表示されないこと。

## フルスクリーン回帰確認

1. テスターがLiteTubeDockをフルスクリーンへ切り替える。
2. テスターがフルスクリーンを解除する。
3. 解除後もタイトルバーが表示されないこと。
4. 解除後も白い外枠が表示されないこと。
5. 解除後も角丸が復活しないこと。
6. URL、再生位置、再生状態が不必要に変化しないこと。
7. 映像が黒画面にならないこと。

## 通常モード確認

1. テスターが `--player-mode` を付けずにLiteTubeDockを起動する。
2. 通常モードでは現在のWindows標準タイトルバーが表示されること。
3. 通常モードでは現在の外枠・角丸・最小化・最大化・閉じる操作が維持されること。

## ファイル混在防止確認

1. テスターが修正版の配布先フォルダーを開く。
2. exe、dll、deps.json、runtimeconfig.jsonの更新日時またはビルド元が同じ成果物であることを確認する。
3. 古いdllが混在していないこと。
4. 実行中のLiteTubeDockが修正版フォルダーのexeを使用していること。

## ログ確認

1. テスターがLiteTubeDock側ログを開く。
2. `PlayerMode=True` が記録されていること。
3. `BorderlessFrameApplied=True` が記録されていること。
4. DWM角丸設定結果を確認できること。
5. DWM境界線色設定結果を確認できること。
6. 適用前後のWin32StyleとWin32ExStyleを確認できること。
7. フルスクリーン解除後の再適用結果を確認できること。

## ビルド確認

- LiteTubeDockのDebugビルドが成功すること
- 警告0件であること
- エラー0件であること
