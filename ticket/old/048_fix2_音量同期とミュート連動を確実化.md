# タスク名

ミキサー音量同期と0%ミュート連動を確実化

# 目的

LiteTubeDockControlのミキサーで設定した音量を、対象プレイヤーへ確実に反映する。

一時停止・ミュート状態から再生した場合でも、ミキサーで設定した音量を無視して100%で再生されないようにする。

また、ミキサーの音量スライダーとミュート状態を以下の仕様で連動させる。

- 0%にしたらミュートON
- 1%以上にしたらミュートOFF
- ミュート中にスライダーを1%以上へ動かしたらミュート解除
- ミュートボタンでミュートしただけの場合は元の音量値を保持

# 実装内容（具体的変更指示）

## 1. 古いポーリング応答を破棄

`RefreshAudioMixerItemAsync` で `get-audio-status` を送信する前に、対象 `AudioMixerItem` の以下を記録する。

- `VolumeOperationGeneration`
- 更新開始時刻
- `IsVolumeDragging`
- `IsVolumeCommandPending`

応答後、以下の場合は `ApplyStatus` しない。

- 応答待ち中に世代が進んだ
- 応答待ち中に音量操作が開始された
- 応答開始時刻より後に新しい音量操作が開始された
- 対象PID・PipeNameが変更された
- Dockが終了・再検出された

## 2. スライダー0%でミュートON

音量スライダーを0%へ確定した場合は、以下の順で送信する。

1. `set-volume 0`
2. 成功確認
3. `set-muted true`
4. 成功確認
5. `get-audio-status`
6. 実値をUIへ反映

## 3. スライダー1%以上でミュートOFF

音量スライダーを1%以上へ確定した場合は、以下の順で送信する。

1. `set-volume N`
2. 成功確認
3. `set-muted false`
4. 成功確認
5. `get-audio-status`
6. 実値をUIへ反映

ミュート中に30%へ動かした場合も、30%＋ミュート解除とする。

## 4. ミュートボタン操作

ミュートボタンでミュートONにした場合は、現在の音量値を保持する。

例：

- 音量30%
- ミュートON
- 表示音量は30%を維持

ミュート解除時は、保持していた30%へ戻す。

## 5. 再生前の音量確定

ミキサーの再生ボタン押下時は、対象Dockの現在ミキサー設定をプレイヤーへ確実に適用してから再生する。

処理順：

1. 対象Dockの設定音量を取得
2. `set-volume`
3. 0%なら `set-muted true`
4. 1%以上なら `set-muted false`
5. `get-audio-status` で実値確認
6. 要求値と一致した場合のみ `play`
7. 再生直後に再度 `get-audio-status`
8. 不一致なら再適用またはエラー表示

## 6. 再生前確認失敗時

音量適用・ミュート適用・実値確認に失敗した場合は、100%で鳴る危険を避けるため、`play` を送信しない。

ユーザーへ短い警告を表示する。

例：

`音量を確認できないため再生を中止しました`

## 7. 再生直後の再確認

`play` 成功後に、短い待機後 `get-audio-status` を再取得する。

実音量が要求値からずれていた場合は、再度 `set-volume` / `set-muted` を送信する。

再試行回数には上限を設ける。

## 8. プレイヤー側変更への追従

YouTube・Twitchのページ内プレイヤーで音量を変更した場合、次回ポーリングで実値をミキサーへ反映する。

Control側の古い値を自動再送して戻さない。

ただし再生ボタン押下時は、ミキサー側の現在設定を優先する。

## 9. Dockごとの独立管理

以下をPID・PipeName単位で独立管理する。

- 設定音量
- 実音量
- ミュート状態
- 音量操作世代
- 保留中コマンド
- 再生前確認状態

同じ動画・同じURLでも共有しない。

## 10. 音量操作中のUI同期

ドラッグ中はポーリング値でThumbを上書きしない。

ドラッグ終了後は、実適用値を取得してUIへ反映する。

`LostMouseCapture`、例外、IPC失敗時でも操作中フラグを解除する。

## 11. タイムスタンプ再生との整合

指定時刻再生時も、以下の順で処理する。

1. `seek-to`
2. `set-volume`
3. `set-muted`
4. 実値確認
5. `play`
6. 再生直後の実値確認

音量確認前に再生しない。

## 12. ミュート表示

以下の状態をUIへ正しく反映する。

- 0%＋ミュートON
- 30%＋ミュートON
- 30%＋ミュートOFF
- 100%＋ミュートOFF

音量0とミュート状態を内部的には別フィールドで保持する。

ただしスライダー操作時は本チケットの連動仕様を適用する。

## 13. エラー処理

以下でControlを異常終了させない。

- IPC未接続
- `set-volume` 失敗
- `set-muted` 失敗
- `get-audio-status` 失敗
- Dock終了
- 応答タイムアウト
- プレイヤー側未対応

他Dockの操作は継続可能にする。

## 14. ログ

以下を記録する。

- DockNumber
- PID
- PipeName
- RequestedVolume
- ActualVolume
- RequestedMuted
- ActualMuted
- VolumeOperationGeneration
- 再生前確認結果
- 再生後確認結果
- 古い応答破棄理由
- ErrorCode
- DurationMs

定期成功ログは大量出力しない。

## 15. 既存機能を壊さない

以下を維持する。

- 音量スライダー
- ミュートボタン
- 一時停止
- 再生
- 指定時刻再生
- `seek-to`
- 全ミュート
- 全ミュート解除
- 16Dock表示
- タブ非表示時のポーリング抑制
- Dockごとの独立管理

## 16. バージョン確認

実装完了時に以下を一致させる。

- アプリ内バージョン表示
- ログ上のバージョン
- `LiteTubeDockControl.csproj`
  - `Version`
  - `AssemblyVersion`
  - `FileVersion`
  - `InformationalVersion`
- exe・dllのファイルバージョン

# 受け入れ条件（目視確認基準）

1. ミキサーで30%へ設定すると対象Dockだけ30%になる。
2. 30%で一時停止後に再生しても100%で鳴らない。
3. ミュート中に30%へ動かすとミュート解除され、30%で再生する。
4. スライダーを0%へ動かすとミュートONになる。
5. 0%から30%へ動かすとミュートOFFになる。
6. ミュートボタンでミュートしても音量値は保持される。
7. ミュート解除で保持音量へ戻る。
8. 再生前に音量・ミュートの実値確認が行われる。
9. 音量確認失敗時は再生を中止する。
10. 再生直後に音量が100%へ戻った場合、検知して再適用する。
11. 古いポーリング応答が新しい音量設定を上書きしない。
12. YouTube側で音量変更するとミキサー表示が追従する。
13. Twitch側で音量変更するとミキサー表示が追従する。
14. 同じ動画を複数Dockで再生しても、音量が独立する。
15. 指定時刻再生でも音量確認後に再生する。
16. Debugビルドが警告0・エラー0で成功する。
17. Releaseビルドが警告0・エラー0で成功する。
18. バージョン定義が一致する。
