# タスク名

チケット013fix2 プレイヤーモードError 153対策と再生オプションUI制御

# 目的

チケット013で、お気に入りごとの `再生モード` として `通常` / `プレイヤー` を追加した。

しかし、`プレイヤー` モードで YouTube embed URL を WebView2 で開いた場合、以下のようなエラーが表示されることがある。

```text
エラー 153
動画プレーヤーの設定エラー
YouTube で動画を見る
```

このため、プレイヤーモード時に WebView2 の `WebResourceRequested` を利用して、YouTube embed 関連リクエストへ安全な範囲で Referer を付与し、Error 153 の回避を試みる。

また、`再生モード = 通常` の場合でも `自動再生` / `ミュート` / `ループ` のチェック項目が操作できるが、これらは基本的にプレイヤーモードの embed URL パラメータとして扱う想定である。

そのため、通常モードではこれらの項目を無効化し、プレイヤーモード選択時のみ有効化する。

# 実装内容（具体的変更指示）

## 1. 作業開始前の確認

- 必ず `AGENT.md` を読むこと。
- 作業対象は `E:\Dev\LiteTubeDock` 配下のみとすること。
- `E:\Dev\LiteTubeDock` の外側にあるファイルやフォルダは一切編集しないこと。
- 既存UIの `x:Name` は原則変更しないこと。
- MainWindow、SettingsWindow、UserControl構成を壊さないこと。
- 既存の設定保存・読み込み・キャンセル・初期値リセット処理を壊さないこと。
- YouTubeのUI改変やDOM操作による自動クリックは行わないこと。

## 2. プレイヤーモードは実験的機能扱いにする

プレイヤーモードは便利だが、YouTube側仕様や動画ごとの埋め込み条件に依存するため、安定保証しない。

仕様として以下を明確にする。

```text
通常モード:
安定重視。YouTube通常ページを開く。

プレイヤーモード:
YouTube embed プレイヤーでの表示を試みる実験的機能。
一部動画では Error 153 などで表示できない場合がある。
その場合は通常モードを使用する。
```

README と HelpContent にこの説明を追記すること。

## 3. WebResourceRequestedでReferer付与を試みる

WebView2初期化後、`CoreWebView2.WebResourceRequested` を利用して、YouTube embed 関連リクエストへ Referer を付与する。

実装候補:

```csharp
PlayerWebView.CoreWebView2.AddWebResourceRequestedFilter(
    "*://www.youtube.com/embed/*",
    CoreWebView2WebResourceContext.All);

PlayerWebView.CoreWebView2.WebResourceRequested += OnWebResourceRequested;
```

Referer例:

```text
https://www.youtube.com/
```

または

```text
https://www.youtube.com
```

## 4. Referer付与対象を限定する

Referer付与は、必要な範囲に限定する。

対象候補:

- `https://www.youtube.com/embed/...`
- `https://www.youtube.com/iframe_api`
- embed再生に関連するYouTubeドメインのリクエスト

避けること:

- Googleログイン関連URLへの不用意なヘッダー付与
- 認証情報やCookieの独自処理
- YouTube以外のURLへのReferer付与
- アプリ内でGoogle ID、パスワード、トークンを扱うこと

## 5. Referer付与処理は安全に失敗させる

WebView2のヘッダー変更ができない場合や例外が出る場合でも、アプリをクラッシュさせないこと。

仕様:

- 例外は握りつぶさず、可能ならステータスバーやデバッグログに安全に出す
- プレイヤーモードが再生できない場合は、既存のYouTubeエラー画面表示を許容する
- Error 153を完全に解消できる保証はしない

## 6. プレイヤーモードで通常ページへ戻す導線は維持する

YouTube embed側で `YouTubeで動画を見る` リンクが表示される場合、その操作を妨げないこと。

今回の目的は Error 153 対策を試みることであり、強制的に通常URLへ戻す処理は必須ではない。

ただし、既存の再生モードを `通常` にすれば通常URLで開けることをREADME/ヘルプに記載すること。

## 7. 再生オプションUIの有効/無効制御

`Views/FavoriteButtonsSettingsView.xaml` の各お気に入りカードで、`再生モード` が `通常` の場合、以下の項目を無効化する。

- `自動再生`
- `ミュート`
- `ループ`

`再生モード` が `プレイヤー` の場合は、上記項目を有効化する。

`リジューム` は通常モードでもプレイヤーモードでも使うため、無効化しない。

仕様:

```text
再生モード = 通常
→ 自動再生 / ミュート / ループ は IsEnabled=false
→ リジューム は IsEnabled=true

再生モード = プレイヤー
→ 自動再生 / ミュート / ループ / リジューム すべて操作可能
```

## 8. UI更新タイミング

以下のタイミングで有効/無効状態を更新する。

- 設定画面を開いた時
- お気に入りボタンカテゴリを表示した時
- `再生モード` ドロップダウンを変更した時
- 初期値に戻した時
- インポート後に設定画面を開いた時

## 9. 見た目上の分かりやすさ

通常モードで無効化されている場合でも、項目自体は表示したままでよい。

README/ヘルプに以下を記載する。

```text
自動再生、ミュート、ループはプレイヤーモード用の補助設定です。
通常モードでは無効になります。
```

## 10. 設定保存の扱い

通常モードで `自動再生` / `ミュート` / `ループ` が無効化されていても、既存保存値は保持してよい。

仕様:

- 通常モードにしたからといって、これらの値を勝手に false に変更しない
- プレイヤーモードに戻した時、以前のチェック状態が復元されてもよい
- 通常モードで遷移する時はこれらの値を原則使用しない

## 11. 再生URL生成との整合性

`FavoritePlaybackUrlService` など、再生URL生成処理がある場合は以下を確認する。

- `PlaybackMode = Normal`
  - 登録URLを基本的にそのまま使う
  - `autoplay` / `mute` / `loop` パラメータは付与しない

- `PlaybackMode = Player`
  - YouTube動画URLなら embed URL に変換する
  - `autoplay` / `mute` / `loop` / `playlist` / `start` などを既存仕様どおり扱う
  - Error 153対策としてReferer付与を試みる

## 12. README更新

READMEに以下を追記する。

- プレイヤーモードは実験的機能であること
- 一部動画では Error 153 などで表示できない場合があること
- その場合は再生モードを `通常` に戻すこと
- 自動再生 / ミュート / ループはプレイヤーモード用の補助設定であること
- 通常モードではこれらの項目が無効化されること
- Error 153対策としてReferer付与を試みるが、完全保証はしないこと

## 13. ヘルプ更新

`Constants/HelpContent.cs` にもREADMEと同等の説明を追記する。

特に以下を明記する。

```text
プレイヤーモードはYouTube embedを使用する実験的機能です。
Error 153などで再生できない場合は、通常モードを使用してください。
```
