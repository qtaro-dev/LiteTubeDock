# LiteTubeDock 形状・角丸部分撤去

## 対象プロジェクト
`E:\Dev\LiteTubeDock`

※ `E:\Dev\LiteTubeDockControl` は変更しないこと。

## 目的
設定画面の「お気に入りボタン」にある以下の項目は、現在のボタン表示へ正しく反映されておらず、設定項目として残す意味も薄いため撤去する。

- 形状
- 角丸

効いていない設定を残すと、利用者の混乱や説明書上の誤解につながるため、UI・保存処理・説明文を整理する。

## 実装内容

### 1. 設定画面から項目を撤去
「お気に入りボタン」設定の各スロットから、以下のUIを削除する。

- 「形状」ラベル
- 形状選択コンボボックス
- 「角丸」チェックボックス

撤去後は、残りの項目が不自然に詰まったり、大きな空白が残ったりしないようにレイアウトを調整する。

### 2. ボタン表示を標準形状へ統一
お気に入りボタンは、現在アプリで使用している標準のボタン形状へ統一する。

形状や角丸の保存値によって見た目を切り替える処理がある場合は削除し、常に同じ見た目になるよう整理する。

### 3. 保存・読み込み処理を整理
形状・角丸に関する以下の処理を調査し、未使用になるものを削除する。

- Model / ViewModel のプロパティ
- UIバインディング
- 保存処理
- 読み込み処理
- 入力検証
- 変換処理
- 定数
- 列挙型
- スタイル切替処理

ただし、既存の設定ファイルやインポートファイルに古い項目が残っていても、読み込みエラーにしないこと。旧項目は無視して正常に読み込める互換性を維持する。

### 4. インポート・エクスポート互換
- 旧形式の設定ファイルを読み込んでもエラーにならないこと
- 形状・角丸以外のお気に入り設定が正常に復元されること
- 新しくエクスポートする設定では、不要であれば形状・角丸項目を出力しないこと
- 既存設計上すぐ削除できない場合も、固定値として機能させず互換用の無視項目として扱うこと

### 5. ヘルプ・説明文を更新
以下から、形状・角丸に関する説明を削除する。

- `HelpContent.cs`
- アプリ内ヘルプ
- README
- docs配下の利用者向け説明
- その他、形状・角丸を利用可能な機能として説明している箇所

開発者向けの過去仕様記録まで無理に改変する必要はないが、現在の利用者向け説明には残さないこと。

### 6. 不要コードの削除
形状・角丸専用で、他の機能から参照されていないコードやリソースは削除する。

共通スタイルや他画面でも使われている処理は削除しないこと。

## 変更しないもの
以下の設定は従来どおり維持する。

- 有効 / 無効
- 表示名
- URL
- アイコン
- 背景色
- 文字色
- 太字
- 再生モード
- 自動再生
- ミュート
- ループ
- リジューム
- お気に入りの保存・削除・インポート・エクスポート

## バージョン
今回はバージョン番号を変更しないこと。

`Version`、`AssemblyVersion`、`FileVersion`、`InformationalVersion` は現状維持とする。

## 受け入れ条件
1. 設定画面の各お気に入りスロットから「形状」と「角丸」が完全に消えている
2. 撤去後のレイアウトに不自然な空白や重なりがない
3. お気に入りボタンが標準形状で正常表示される
4. 既存のお気に入り設定が失われない
5. 旧設定ファイルを読み込んでもエラーにならない
6. インポート・エクスポートが正常に動作する
7. `HelpContent.cs` などの利用者向け説明から形状・角丸の説明が削除されている
8. Debug / Release ビルドが警告0・エラー0で成功する
9. LiteTubeDockControl側に変更が入っていない
10. バージョン番号が変更されていない

## 確認手順
1. LiteTubeDockを起動する
2. 設定画面を開く
3. 「お気に入りボタン」を選ぶ
4. お気に入り01～10の各欄に「形状」と「角丸」が表示されていないことを確認する
5. 背景色、文字色、太字、再生設定など、残した項目を変更する
6. 「保存」を押す
7. メイン画面のお気に入りボタンへ変更内容が反映されることを確認する
8. アプリを終了して再起動する
9. 保存した内容が維持されていることを確認する
10. 旧形式の設定ファイルをインポートする
11. エラーが出ず、形状・角丸以外の設定が正常に復元されることを確認する
12. ヘルプを開き、形状・角丸を選べるという説明が残っていないことを確認する

実装完了時は、以下を報告すること。

- 変更したファイル
- 削除したUI・プロパティ・処理
- 旧設定ファイルとの互換方法
- ヘルプ更新箇所
- Debug / Release ビルド結果
- 未対応事項や残存コードがある場合は、その理由
