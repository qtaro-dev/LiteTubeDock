# タスク名

YouTube Shortsリサイズ後の映像描画停止を安全に再描画する修正

# 目的

LiteTubeDockでYouTube Shortsを再生中にウィンドウサイズを変更すると、音声と再生時間は進み続けているにもかかわらず、映像だけが数秒間停止して見える問題を改善する。

チケット039で追加した診断ログにより、問題発生時も以下が維持されていることを確認済み。

- `paused=False`
- `currentTime` が進行
- `readyState=4`
- URL変更なし
- `currentSrc`変更なし
- 同一動画判定
- Navigationなし
- video要素の表示サイズが0ではない

したがって、再生状態・URL・再生位置へ触れず、リサイズ完了後にWebView2およびvideo描画面の再描画だけを安全に促す。

# 実装内容（具体的変更指示）

1. チケット039で実装したリサイズ完了検知処理を利用すること。

2. リサイズ中に毎回再描画処理を実行しないこと。

3. リサイズ操作停止後、デバウンスされた1回だけ再描画補助処理を実行すること。

4. デバウンス時間は200～500ms程度を目安とし、既存のリサイズ診断処理と整合させること。

5. 再描画補助の対象は、現在表示中のページがYouTube Shortsである場合を優先すること。

6. Shorts判定には、少なくとも現在URLの `/shorts/` を利用すること。

7. 通常の横動画や他サイトへ不要な再描画処理を適用しないこと。

8. 再描画補助を実行する前に、以下を確認すること。

   - WebView2が初期化済み
   - CoreWebView2が利用可能
   - ウィンドウが最小化されていない
   - WebView2の実表示幅・高さが0より大きい
   - 現在URLがShorts
   - video要素が存在する
   - 対象video要素が表示中
   - `paused=False`または一時停止状態が取得可能
   - Navigation中ではない

9. 再描画補助は、URL再読込を行わないこと。

10. `Reload()`、`Navigate()`、HOME URL再適用、履歴移動を使用しないこと。

11. `play()`、`pause()`、`currentTime`変更、`muted`変更を通常の再描画手段として使用しないこと。

12. 再生状態や再生位置を変えずに、以下のような安全な再描画手段を段階的に検討すること。

   - WPF側の`InvalidateVisual`
   - `UpdateLayout`
   - WebView2コンテナのレイアウト再評価
   - WebView2の実表示サイズ再適用
   - サイズを変更せずに再配置通知
   - video要素または親要素への軽量なCSS再評価
   - `requestAnimationFrame`を利用した表示更新
   - video要素のtransformを一時的に変更して即時復元
   - 1px未満または視覚上変化しない軽微な描画トリガー

13. JavaScript側で再描画を促す場合は、以下を満たすこと。

   - video要素を現在DOMから再取得する
   - 古いDOM参照を保持しない
   - video要素の再生状態を変更しない
   - `currentTime`を変更しない
   - `src`を変更しない
   - DOM要素を削除・再作成しない
   - ページ全体を再読込しない

14. 再描画補助は一度のリサイズ完了につき最大1回とすること。

15. 1回の再描画補助で改善しない場合でも、連続ループや無限再試行を行わないこと。

16. 必要に応じて、最大2段階までの安全なフォールバックを許可すること。

17. フォールバック例:

   1. WPF/WebView2レイアウト更新
   2. video要素への軽量なCSS再描画トリガー

18. 2段階目まで実行しても改善しない場合は、ログ記録だけ行い、それ以上の強制処理は行わないこと。

19. 一時停止中のShortsでは、再描画補助後も一時停止状態を維持すること。

20. 再生中のShortsでは、再描画補助後も再生状態を維持すること。

21. 再描画補助前後で以下を比較すること。

   - CurrentUrl
   - currentSrc
   - paused
   - currentTime
   - readyState
   - videoWidth
   - videoHeight
   - 表示幅
   - 表示高さ

22. 再描画補助によってURL・動画・一時停止状態・再生位置が変化した場合は、異常としてログへ記録すること。

23. リサイズ完了時に、以下の診断ログを追加すること。

   - `RenderRefreshRequested`
   - `RenderRefreshStep1Started`
   - `RenderRefreshStep1Completed`
   - `RenderRefreshStep2Started`
   - `RenderRefreshStep2Completed`
   - `RenderRefreshSkipped`
   - `RenderRefreshStateChangedUnexpectedly`

24. 各ログには少なくとも以下を含めること。

   - ProcessId
   - CurrentUrl
   - WindowWidth
   - WindowHeight
   - WebViewWidth
   - WebViewHeight
   - paused
   - currentTime
   - readyState
   - currentSrc
   - videoWidth
   - videoHeight
   - 表示幅
   - 表示高さ
   - 実行した再描画手段
   - 実行結果
   - スキップ理由
   - 処理時間
   - 例外内容

25. 既存のログマスク方針を維持すること。

26. Cookie、認証情報、トークン、ページ本文等を追加記録しないこと。

27. ログ書込失敗でアプリを異常終了させないこと。

28. チケット038のログ専用ウィンドウで追加ログを閲覧・検索・コピーできること。

29. チケット039で修正済みの以下を壊さないこと。

   - フルスクリーン切替で過去Shortsへ戻らない
   - 一時停止中にフルスクリーンへ切り替えても勝手に再生されない
   - 再生中・一時停止中の状態保持
   - URL再遷移防止
   - 同一動画維持

30. 通常動画、YouTubeトップページ、ライブ配信、他サイトの表示を壊さないこと。

31. Debug構成でビルドし、警告0・エラー0を確認すること。

# 受け入れ条件（目視確認基準）

## 事前条件

- LiteTubeDockを1台だけ起動する
- 既存ログを削除または空にする
- YouTube Shortsを最初の1本目から再生する
- ログ専用ウィンドウを開ける状態にする

## 数pixelだけ横へ拡大

1. Shortsを細長いカスタムサイズで再生する。
2. 再生が安定していることを確認する。
3. ウィンドウ右端をドラッグし、横幅を2～5px程度だけ広げる。
4. 映像が数秒間停止して見えないことを確認する。
5. 音声と映像が継続して同期することを確認する。
6. 別アプリへフォーカス移動しなくても、そのまま映像が動き続けることを確認する。
7. URL、Shorts内容、再生位置が大きく変わらないことを確認する。

## 数pixelだけ縮小

1. 同じShortsを再生したまま、横幅を2～5px程度だけ狭くする。
2. 映像が停止して見えないことを確認する。
3. 音声のみ進み続ける状態にならないことを確認する。
4. 別アプリへフォーカス移動しなくても映像が継続することを確認する。

## 数pixelだけ縦方向変更

1. Shorts再生中に、高さを2～5px程度だけ変更する。
2. 映像が停止して見えないことを確認する。
3. 再生状態が変化しないことを確認する。

## 大きなリサイズ

1. 細長いカスタムサイズから、横方向へ大きく広げる。
2. 映像が10秒程度停止して見える現象が再発しないことを確認する。
3. 音声と映像が継続することを確認する。
4. 同じShortsが維持されることを確認する。
5. 数個前のShortsへ戻らないことを確認する。

## 一時停止中

1. Shortsを一時停止する。
2. 横幅を2～5px程度変更する。
3. 切替後も一時停止状態を維持することを確認する。
4. 勝手に再生されないことを確認する。
5. 画面が真っ黒にならないことを確認する。

## フォーカス移動なし

1. Shorts再生中にリサイズする。
2. リサイズ後、別アプリへフォーカスを移さず10秒程度待つ。
3. 映像が止まったままにならないことを確認する。
4. フォーカス復帰を再描画トリガーとして必要としないことを確認する。

## 連続微調整

1. Shorts再生中に、横幅を2～5pxずつ複数回変更する。
2. 各変更後に映像が継続することを確認する。
3. リサイズ処理が重複してアプリが固まらないことを確認する。
4. ログが過剰な無限出力になっていないことを確認する。

## ログ確認

1. ログウィンドウを開く。
2. リサイズを実行する。
3. `RenderRefreshRequested` が記録されることを確認する。
4. 実行された再描画手段が確認できることを確認する。
5. 再描画前後のpaused、currentTime、currentSrc、readyStateが確認できることを確認する。
6. URL・currentSrc・paused状態が不正に変化していないことを確認する。
7. 再描画処理時間が確認できることを確認する。
8. 対象外ページでは`RenderRefreshSkipped`とスキップ理由が確認できること。

## 通常動画との比較

1. 通常の横型YouTube動画を再生する。
2. 数pixelだけサイズ変更する。
3. 不要なShorts専用再描画処理が適用されないことをログで確認する。
4. 通常動画の再生が壊れていないことを確認する。

## フルスクリーン回帰確認

1. Shorts再生中にAlt+Enterでフルスクリーンへ切り替える。
2. 映像が真っ黒にならないことを確認する。
3. 過去Shortsへ戻らないことを確認する。
4. 一時停止中の場合は一時停止を維持することを確認する。
5. フルスクリーン解除後も同じ状態を維持することを確認する。

## 回帰確認

- WebView2の通常表示が動作すること
- アドレスバー、戻る、進む、再読込、ホームが動作すること
- お気に入りボタンが動作すること
- IPCの再生、一時停止、ミュート、巻き戻しが動作すること
- 初期停止が動作すること
- ログ専用ウィンドウが動作すること
- 通常モードとプレイヤーモードの両方で異常終了しないこと
- Debug構成で警告0・エラー0でビルド成功すること
