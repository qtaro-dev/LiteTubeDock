# タスク名

チケット012fix2 バージョン情報ウィンドウの本文切れ再修正

# 目的

チケット012fix1で `バージョン情報` ウィンドウの表示崩れ修正と開発者情報追加を行ったが、まだ下部の `セキュリティ方針` 本文が途中で切れて表示されている。

現在の表示では、以下の文言が下部で見切れている。

```text
Google ID、パスワード、認証トークンは保存しません。
```

AboutWindowの本文全体がウィンドウ内に収まるように、単純な枠サイズ調整だけではなく、レイアウト構造を見直して、本文が必ず読めるようにする。

# 実装内容（具体的変更指示）

## 1. 作業開始前の確認

- 必ず `AGENT.md` を読むこと。
- 作業対象は `E:\Dev\LiteTubeDock` 配下のみとすること。
- `E:\Dev\LiteTubeDock` の外側にあるファイルやフォルダは一切編集しないこと。
- 既存UIの `x:Name` は原則変更しないこと。
- MainWindow、SettingsWindow、HelpWindow、既存機能を壊さないこと。

## 2. AboutWindowのレイアウトを見直す

単純にウィンドウサイズを少し広げるだけでは再発するため、`AboutWindow.xaml` の全体構造を以下のように見直す。

推奨構成:

```text
Window
└─ Grid
   ├─ 本文エリア（ScrollViewer）
   └─ 下部ボタンエリア
```

推奨Grid行:

```xml
<Grid.RowDefinitions>
    <RowDefinition Height="*" />
    <RowDefinition Height="Auto" />
</Grid.RowDefinitions>
```

本文は `ScrollViewer` 内に置き、下部の `閉じる` ボタンは別行に固定すること。

## 3. 本文エリアをScrollViewer化する

AboutWindow本文全体を `ScrollViewer` で囲み、ウィンドウサイズが足りない場合でもスクロールして全文を読めるようにする。

仕様:

- セキュリティ方針が見切れない
- ウィンドウが小さい場合でもスクロールで読める
- `閉じる` ボタンはスクロール領域に巻き込まれず、下部に表示される
- 縦スクロールは必要時のみ表示でよい

推奨:

```xml
<ScrollViewer Grid.Row="0"
              VerticalScrollBarVisibility="Auto"
              HorizontalScrollBarVisibility="Disabled">
```

## 4. TextBlockの折り返しを徹底する

本文内の説明文 `TextBlock` には、必ず折り返し設定を入れる。

推奨:

```xml
TextWrapping="Wrap"
```

必要に応じて以下も設定する。

```xml
TextTrimming="None"
HorizontalAlignment="Stretch"
```

横スクロールに頼らず、ウィンドウ幅に合わせて折り返すこと。

## 5. セキュリティ方針を2行以上に分ける

セキュリティ方針は1行に詰めず、明示的に複数行で表示する。

推奨表示:

```text
Google ID、パスワード、認証トークンは保存しません。
YouTubeログイン状態はWebView2標準のCookie/session管理に任せます。
```

この2行が最後まで読めること。

## 6. AboutWindowの初期サイズを再調整する

AboutWindowの初期サイズを、本文が見やすい程度に調整する。

推奨:

```text
Width: 520
Height: 500
```

または、既存画面とのバランスを見て同等以上のサイズにすること。

ただし、初期サイズに依存せず、ScrollViewerで本文が読める構造にすること。

## 7. 閉じるボタンの配置を安定させる

`閉じる` ボタンは下部に固定表示する。

仕様:

- 本文が長くてもボタンが隠れない
- ウィンドウ下部の右側、または中央寄せに表示する
- 既存の `CloseAboutButton` がある場合は維持する
- `閉じる` ボタンでウィンドウを閉じられること

## 8. 開発者情報は維持する

チケット012fix1で追加した以下の表示は維持する。

```text
開発者: Qtaro
開発支援: GPT / CODEX
```

これらが見切れず表示されること。

## 9. README更新

READMEに変更内容を追記する必要は基本的にない。

ただし、READMEにバージョン情報画面の説明がある場合は、表示崩れ修正と矛盾しないように確認すること。

## 10. 実装しないこと

- ライセンス一覧画面
