# チケット027fix1: ナビゲーションボタンのサイズとホバー表示を統一する

## 目的

チケット027で MainWindow 上部に「戻る」「進む」「再読み込み」「ホーム」のナビゲーションボタンを追加した。

現在、4つのボタンは表示されているが、実際に画面で確認すると以下の違和感がある。

- ボタン全体のサイズが小さい
- アイコンが小さく見える
- 再読み込み・ホームにはマウスオーバー時の枠が出る
- 戻る・進むには同じマウスオーバー枠が出ず、見た目が統一されていない

4つのナビゲーションボタンを、同じサイズ・同じホバー表示・同じ押下表示に揃え、上部ツールバーとして自然に見えるようにする。

## 前提

- 作業対象は `E:\Dev\LiteTubeDock` 配下のみとする。
- `E:\Dev\backup_LiteTubeDock` は編集しない。
- AGENT.md が存在する場合は、その内容を最優先で確認・遵守する。
- 既存設計、既存テーマ、既存ライブラリ構成を壊さない。
- 既存 `x:Name` は原則維持する。
- YouTube / Google のログイン、認証情報、広告、DOM操作、WebView2まわりの仕様には触れない。
- YouTube広告を自動キャンセル、非表示、削除、置換、スキップする機能は実装しない。
- DOM操作、自動クリック、YouTube内部API呼び出しは行わない。
- 今回はチケット027で追加したナビゲーションボタンの見た目調整のみを対象とする。

## 対象ファイル

推定対象:

- `MainWindow.xaml`
- `MainWindow.xaml.cs`
- 必要に応じて共通Style定義
- 必要に応じて画像リソース参照設定

使用中のアイコン画像:

```text
E:\Dev\LiteTubeDock\Resource\Left.png
E:\Dev\LiteTubeDock\Resource\Right.png
E:\Dev\LiteTubeDock\Resource\RELOAD.png
E:\Dev\LiteTubeDock\Resource\HOME.png
```

## 現状

MainWindow 上部のアドレスバー左側に、以下4つのボタンが表示されている。

- 戻る
- 進む
- 再読み込み
- ホーム

ただし、画面確認上、ボタンの大きさが小さく、マウスオーバー時の枠表示もボタンごとに統一されていない。

特に、再読み込み・ホームはマウスオーバー時に枠が出るが、戻る・進むには同じ枠が出ないため、UIとして違和感がある。

## 実装内容

### 1. ナビゲーション4ボタンのサイズを統一する

以下4つのボタンの `Width` / `Height` を統一する。

- 戻る
- 進む
- 再読み込み
- ホーム

推奨サイズ:

```text
Width: 32〜36
Height: 28〜32
```

実際の上部ツールバーの高さに合わせ、自然に見えるサイズを選ぶ。

要件:

- 4つのボタンサイズが同じであること。
- 小さすぎて押しづらくないこと。
- 大きすぎてアドレスバーを圧迫しないこと。
- 上部行の高さが不自然に大きくならないこと。

### 2. アイコン画像サイズを統一する

ボタン内のアイコン画像サイズを統一する。

推奨:

```text
Image Width: 18〜22
Image Height: 18〜22
```

要件:

- 4つのアイコンが同じ見え方の大きさになること。
- 画像がボタン中央に配置されること。
- 画像がボタンからはみ出さないこと。
- アイコンが小さすぎて意味が分からなくならないこと。

### 3. 4ボタンで同じ Button Style を使用する

戻る・進む・再読み込み・ホームの4ボタンは、同じ Button Style を使う。

揃える項目:

- `BorderBrush`
- `BorderThickness`
- `Background`
- `Padding`
- `Margin`
- `HorizontalContentAlignment`
- `VerticalContentAlignment`
- `MouseOver` 時の背景・枠
- `Pressed` 時の背景・枠
- `Disabled` 時の表示

要件:

- 再読み込み・ホームだけ枠が出る状態にしない。
- 戻る・進むだけ枠が出ない状態にしない。
- 4ボタンともマウスオーバー時に同じ見た目になること。
- 4ボタンとも押下時に同じ見た目になること。

### 4. マウスオーバー時の枠表示を統一する

マウスオーバーしたボタンに、4つすべて同じ枠または背景変化が出るようにする。

期待イメージ:

- 戻るにマウスを乗せる → 枠または背景が出る
- 進むにマウスを乗せる → 同じ枠または背景が出る
- 再読み込みにマウスを乗せる → 同じ枠または背景が出る
- ホームにマウスを乗せる → 同じ枠または背景が出る

### 5. 無効状態の見た目も揃える

戻る・進むが履歴状態に応じて無効化される場合は、無効時の見た目も自然にする。

要件:

- 無効時にアイコンが極端に見えなくならないこと。
- 有効/無効の違いが分かること。
- 無効時でも他ボタンとレイアウトがずれないこと。

### 6. ToolTip は維持する

チケット027で追加した ToolTip は維持する。

- 戻る
- 進む
- 再読み込み
- ホーム

## 実装時の注意

- 画像ファイル自体を変更しなくてもよい。
- まずは XAML 側の Button / Image サイズ、Style、Padding、Margin の調整を優先する。
- 画像側に余白が多く、XAML調整だけでは見た目が揃わない場合は、その旨を報告する。
- アドレスバーの横幅を大きく圧迫しない。
- 「移動」「現在URLをコピー」ボタンの配置を崩さない。
- メニュー行や WebView2 表示位置を不自然にずらさない。
- 既存のクリック処理・ショートカット処理を壊さない。
- YouTube / Google / WebView2 関連の処理には触れない。

## 受け入れ条件（目視確認基準）

### サイズ確認

1. LiteTube Dock を起動する。
2. MainWindow 上部を見る。
3. 戻る・進む・再読み込み・ホームの4ボタンが同じサイズで表示されていることを確認する。
4. ボタンが小さすぎず、押しやすい大きさになっていることを確認する。
5. アドレスバーが極端に狭くなっていないことを確認する。

### アイコン確認

1. 4つのアイコンがボタン中央に表示されていることを確認する。
2. 4つのアイコンの見た目サイズが自然に揃っていることを確認する。
3. アイコンがボタンからはみ出していないことを確認する。

### ホバー表示確認

1. 戻るボタンにマウスを乗せる。
2. 枠または背景変化が出ることを確認する。
3. 進むボタンにマウスを乗せる。
4. 戻るボタンと同じ見た目の枠または背景変化が出ることを確認する。
5. 再読み込みボタンにマウスを乗せる。
6. 同じ見た目の枠または背景変化が出ることを確認する。
7. ホームボタンにマウスを乗せる。
8. 同じ見た目の枠または背景変化が出ることを確認する。

### 動作確認

1. 戻るボタンを押して、WebView2 の履歴を戻れることを確認する。
2. 進むボタンを押して、WebView2 の履歴を進めることを確認する。
3. 再読み込みボタンを押して、現在ページを再読み込みできることを確認する。
4. ホームボタンを押して、設定済みホームURLへ移動できることを確認する。
5. 各ボタンの ToolTip が表示されることを確認する。

### 既存機能確認

- アドレスバーの URL入力・貼り付け・移動が動作する。
- 「移動」ボタンが動作する。
- 「現在URLをコピー」ボタンが動作する。
- ファイルメニュー、表示メニュー、設定メニュー、ヘルプメニューが開ける。
- お気に入りボタンが動作する。
- 設定画面、ヘルプ画面、バージョン情報画面を開ける。
- YouTube / Google / WebView2 関連の挙動に変更が入っていない。

## 補足

今回の主目的は、チケット027で追加したナビゲーションボタンを「同じ部品」として自然に見えるように揃えることである。

特に以下の違和感を解消する。

- ボタンが小さい
- 再読み込み・ホームだけホバー枠が出る
- 戻る・進むだけホバー枠が出ない
- 4ボタンの見た目が揃っていない
