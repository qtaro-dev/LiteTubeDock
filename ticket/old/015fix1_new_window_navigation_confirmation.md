# タスク名

チケット015fix1 新規ウィンドウ要求の外部リンク遷移確認追加

# 目的

チケット015で、WebView2の通常遷移に対して `動画ページ以外への遷移を確認する` 機能を追加した。

しかし、YouTube画面内のスポンサーリンクなどをクリックした場合、通常のページ遷移ではなく、新規ウィンドウまたはポップアップ扱いで外部サイトが開かれる場合がある。

この場合、既存の `NavigationStarting` だけでは確認ダイアログを出せず、外部サイトが開いてしまう。

そのため、WebView2の `NewWindowRequested` も捕まえ、YouTube外URLまたは動画ページ以外と思われるURLへ新規ウィンドウ遷移しようとした場合にも、同じ確認メッセージを表示する。

この機能は広告ブロックではなく、誤クリック防止のための外部遷移確認である。

# 実装内容（具体的変更指示）

## 1. 作業開始前の確認

- 必ず `AGENT.md` を読むこと。
- 作業対象は `E:\Dev\LiteTubeDock` 配下のみとすること。
- `E:\Dev\LiteTubeDock` の外側にあるファイルやフォルダは一切編集しないこと。
- 既存UIの `x:Name` は原則変更しないこと。
- MainWindow、SettingsWindow、HelpWindow、AboutWindow、既存機能を壊さないこと。
- YouTube広告をブロック、非表示、改変、置換、スキップする機能として実装しないこと。
- YouTubeのDOM操作や内部API操作は行わないこと。

## 2. NewWindowRequestedを処理する

WebView2初期化後、`CoreWebView2.NewWindowRequested` を購読する。

実装候補:

```csharp
PlayerWebView.CoreWebView2.NewWindowRequested += OnNewWindowRequested;
```

すでにWebView2初期化処理内でイベント登録している箇所がある場合は、そこに追加すること。

## 3. 新規ウィンドウ要求のURLを判定する

`NewWindowRequested` 発生時に、要求先URLを取得する。

実装候補:

```csharp
var targetUrl = e.Uri;
```

取得したURLに対して、チケット015で追加したURL判定と同じ考え方を使う。

基本方針:

- YouTube系URLは許可
- YouTube以外の外部URLは確認対象
- 不明なスキームも確認対象または安全にキャンセル
- null/空文字/不正URLでもクラッシュしない

## 4. 確認メッセージを表示する

YouTube外、または動画ページ以外と思われるURLへ新規ウィンドウが開こうとした場合、以下の文言で確認する。

```text
動画ページ以外へ移動しようとしています。
遷移してよろしいですか？
```

推奨ボタン:

```text
はい / いいえ
```

挙動:

- `はい`: 遷移を許可
- `いいえ`: 新規ウィンドウを開かせない

広告やスポンサーとは断定しないこと。

## 5. いいえの場合は新規ウィンドウを開かせない

ユーザーが `いいえ` を選んだ場合、WebView2の新規ウィンドウ要求を処理済みにして、外部サイトが開かれないようにする。

実装候補:

```csharp
e.Handled = true;
```

必要に応じて、`e.NewWindow` は設定しない。

ステータスバーへ以下のような表示をしてよい。

```text
状態: 動画ページ以外への遷移をキャンセルしました
```

## 6. はいの場合の遷移先処理

ユーザーが `はい` を選んだ場合の動作を決める。

推奨方針:

```text
同じLiteTube Dock内のWebViewで対象URLへ遷移する
```

理由:

- 予期せず外部ブラウザや別WebViewウィンドウが開くのを避ける
- LiteTube Dock内で状態を把握しやすい
- 誤クリック防止の延長として自然

実装候補:

```csharp
e.Handled = true;
PlayerWebView.CoreWebView2.Navigate(targetUrl);
```

ただし、既存方針で外部ブラウザを使う実装がある場合は、それと矛盾しないようにする。

## 7. YouTube系URLの場合

YouTube系URLの新規ウィンドウ要求は、確認なしで同じWebView内で開いてよい。

推奨:

```text
YouTube系URLのNewWindowRequested
↓
e.Handled = true
↓
同じWebView内でNavigate
```

理由:

- 新しい別ウィンドウが増えるのを避ける
- YouTube操作をLiteTube Dock内に収める
- 通常の動画・チャンネル・検索への導線を壊しにくい

許可対象例:

```text
https://www.youtube.com/
https://youtube.com/
https://m.youtube.com/
https://youtu.be/
https://www.youtube-nocookie.com/
```

## 8. 設定OFF時の挙動

`動画ページ以外への遷移を確認する` がOFFの場合は、新規ウィンドウ要求でも確認を出さない。

ただし、別ウィンドウを増やさないため、以下の方針を推奨する。

```text
確認OFF時も e.Handled = true にして、同じWebView内でNavigateする
```

これにより、LiteTube Dock外へ勝手に新規ウィンドウが増えるのを避ける。

## 9. NavigationStartingとの重複確認に注意する

`NewWindowRequested` で `PlayerWebView.CoreWebView2.Navigate(targetUrl)` した場合、その後 `NavigationStarting` が発生する可能性がある。

この場合、同じURLに対して二重に確認ダイアログが出ないようにする。

方針例:

- NewWindowRequestedでユーザーが許可した場合、一時的なスキップフラグを立てる
- アプリ操作スキップ用の既存フラグがある場合はそれを再利用する
- NavigationStarting側では、そのフラグが立っている場合は確認をスキップする

## 10. 明示的なアプリ操作との整合性

チケット015で確認スキップ対象にしている以下の操作は引き続き壊さないこと。

- アドレスバー移動
- Home
- Reload
- お気に入りボタン
- 起動時URL復元
- Back / Forward の既存方針

## 11. 広告ブロックではないことを維持する

今回の修正でも以下は行わない。

- YouTube広告の検出
- YouTube広告の非表示
- YouTube広告のスキップ
- スポンサーリンクの自動判定
- 広告部分のクリック不能化
- YouTube DOM操作
- YouTube UIの改変
- YouTube内部API操作

あくまでも、新規ウィンドウ要求として外部URLへ移動しようとした時の確認である。

## 12. README更新

READMEのチケット015相当の説明に、以下を追記する。

- WebView内の通常遷移だけでなく、新規ウィンドウ要求でも外部リンク確認を行うこと
- 確認OFF時でも、可能な範囲で同じLiteTube Dock内に遷移させること
- この機能は広告ブロックではないこと

## 13. ヘルプ更新

# 受け入れ条件（目視確認基準）

## ビルド確認

- `dotnet build` でビルドエラーがない
- 警告が出る場合は内容を報告すること
- アプリ起動時にクラッシュしない

## 新規ウィンドウ要求確認

- `動画ページ以外への遷移を確認する` がONの状態で、YouTube内のスポンサーリンクなど、新規ウィンドウ扱いになりそうな外部リンクをクリックする
- 以下の確認メッセージが表示される

```text
動画ページ以外へ移動しようとしています。
遷移してよろしいですか？
```

- `いいえ` を選ぶと外部サイトへ遷移しない
- 別ウィンドウが開かない
- ステータスバーにキャンセル状態が表示される、またはキャンセルされたことが分かる

## 許可確認

- 同じ確認メッセージで `はい` を選ぶ
- 遷移が許可される
- 可能であれば同じLiteTube Dock内のWebViewで開かれる
- アプリがクラッシュしない

## YouTube系URL確認

- YouTube内の動画、チャンネル、検索、ショート、ライブなどのリンク操作が壊れていない
- YouTube系URLの新規ウィンドウ要求が発生した場合でも、不要な確認が出すぎない
- 必要なら同じWebView内で開かれる

## 設定OFF確認

- `動画ページ以外への遷移を確認する` をOFFにして保存する
- 新規ウィンドウ扱いの外部リンクでも確認が出ない
- 可能であれば同じWebView内で遷移する
- アプリがクラッシュしない

## 二重確認防止

- 外部リンクをクリックした時、同じURLに対して確認ダイアログが2回連続で出ない
- `NewWindowRequested` と `NavigationStarting` の両方で二重確認されない

## 広告ブロックではないことの確認

- YouTube広告を非表示にしない
- YouTube広告をスキップしない
- YouTubeプレイヤー上の広告表示を改変しない
- DOM操作や内部API操作をしていない

## 既存機能確認

- 通常モードのお気に入り再生が壊れていない
- プレイヤーモードが壊れていない
- プレイヤーモードReferer設定が壊れていない
- プレイヤーモード診断が壊れていない
- アドレスバーが壊れていない
- アドレスバーの現在URL同期が壊れていない
- お気に入り右クリック登録が壊れていない
- お気に入りボタンの色・アイコン表示が壊れていない
- リジューム設定が壊れていない
- インポート/エクスポートが壊れていない
- フルスクリーン切り替えが壊れていない
- ウィンドウサイズプリセットが壊れていない
