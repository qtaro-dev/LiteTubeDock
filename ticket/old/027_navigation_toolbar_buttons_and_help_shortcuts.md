# チケット027: ナビゲーションツールバーボタン追加とヘルプのショートカット追記

## 目的

MainWindow の上部には現在、アドレスバー・移動・現在URLコピーがあるが、
ブラウザ的に頻繁に使う「戻る」「進む」「再読み込み」「ホーム」の常設ボタンがない。

ファイルメニューやキーボードショートカットでは操作できるが、
一目で分かる常設のナビゲーションボタンを追加して、操作性を上げたい。

あわせて、ヘルプ画面にも対応ショートカットとボタン説明を追記する。

## 前提

- 作業対象は `E:\Dev\LiteTubeDock` 配下のみとする。
- `E:\Dev\backup_LiteTubeDock` は編集しない。
- AGENT.md が存在する場合は、その内容を最優先で確認・遵守する。
- 既存設計、既存テーマ、既存ライブラリ構成を壊さない。
- 既存 `x:Name` は原則維持する。
- YouTube / Google のログイン、認証情報、広告、DOM操作、WebView2まわりの仕様には触れない。
- YouTube広告を自動キャンセル、非表示、削除、置換、スキップする機能は実装しない。
- DOM操作、自動クリック、YouTube内部API呼び出しは行わない。
- 今回は MainWindow のナビゲーションボタン追加と HelpWindow の文言追記のみを対象とする。

## 対象ファイル

推定対象:

- `MainWindow.xaml`
- `MainWindow.xaml.cs`
- `HelpWindow.xaml`
- `HelpWindow.xaml.cs`
- 必要に応じて共通コマンド処理
- 必要に応じて画像リソース参照設定
- アイコン配置先候補:
  - `Resources/Icons/`
  - または `Resources/Images/`

## 背景

現在は以下の操作がメニューやショートカットで可能な想定だが、常設ボタンがない。

- 戻る
- 進む
- 再読み込み
- ホーム

ユーザーの希望としては、スクリーンショット案のように、アドレスバーの左側にこれらのコントロール系ボタンを並べたい。

また、これらは文字ボタンではなく、アイコンで一目で分かるようにしたい。

## 実装内容

### 1. MainWindow 上部にナビゲーションボタンを追加する

アドレスバーの左側に、以下4つのボタンを追加する。

- 戻る
- 進む
- 再読み込み
- ホーム

推奨配置:

```text
[戻る] [進む] [再読み込み] [ホーム] [アドレスバー] [移動] [現在URLをコピー]
```

配置意図:

- URL移動系の操作を同じ行にまとめる
- 一般的なブラウザ操作に近い見た目にする
- ファイルメニューから開かなくても使えるようにする

### 2. ボタンはアイコン表示にする

各ボタンはテキストではなく、分かりやすいアイコン表示にする。

対象アイコン:

- 戻る: 左向き矢印
- 進む: 右向き矢印
- 再読み込み: 円形矢印
- ホーム: 家のアイコン

要件:

- 一目で意味が分かること
- 同系統のデザインに揃えること
- 小さすぎず、大きすぎないこと
- 既存の上部レイアウトを壊さないこと
- ボタンのツールチップに操作名を出してもよい

推奨ファイル名例:

```text
Resources/Icons/nav_back.png
Resources/Icons/nav_forward.png
Resources/Icons/nav_reload.png
Resources/Icons/nav_home.png
```

または `.ico` / DrawingImage / Path でも可。
実装しやすい方法を採用してよい。

### 3. 既存メニュー操作と同じ処理を呼ぶ

追加する各ボタンは、既存のメニュー項目と同じ処理を呼ぶようにする。

- 戻るボタン → 既存の「戻る」処理
- 進むボタン → 既存の「進む」処理
- 再読み込みボタン → 既存の「再読み込み」処理
- ホームボタン → 既存の「ホーム」処理

Enterキー用やメニュー用に別処理が増えすぎないよう、共通化できるなら共通化する。

### 4. ボタン有効/無効状態を適切にする

可能であれば、以下の有効/無効制御を行う。

- 戻る: `CanGoBack` が `true` のとき有効
- 進む: `CanGoForward` が `true` のとき有効
- 再読み込み: WebView2 が利用可能なら有効
- ホーム: 常に有効でよい

必須ではないが、できるだけ自然なブラウザ挙動に寄せる。

### 5. キーボードショートカットは維持する

既存のショートカットは維持する。

想定対象:

- 戻る: `Alt + ←`
- 進む: `Alt + →`
- 再読み込み: `F5`
- ホーム: 既存仕様に合わせる

### 6. ヘルプ画面にボタン説明とショートカットを追記する

ヘルプ画面の「基本操作」付近に、ナビゲーションボタンとショートカットの説明を追記する。

追記例:

```text
・戻る: 戻るボタン、または Alt + ← でWebView2の履歴を1つ戻ります。
・進む: 進むボタン、または Alt + → でWebView2の履歴を1つ進みます。
・再読み込み: 再読み込みボタン、または F5 で現在のページを再読み込みします。
・ホーム: ホームボタンで設定済みのホームURLへ移動します。
```

文言は既存ヘルプに合わせて自然に整えてよい。

### 7. 上部レイアウトの横幅バランスを調整する

ナビゲーションボタン追加後も、以下を維持する。

- アドレスバーが十分な横幅を持つ
- 「移動」ボタンが押しやすい
- 「現在URLをコピー」ボタンが押しやすい
- ウィンドウ幅が狭い時でも極端に崩れない

必要に応じて:

- アイコンボタン幅を固定
- アドレスバーを残り幅いっぱいにする
- 余白を微調整する

## 実装時の注意

- アイコンだけでは分かりづらい場合は `ToolTip` を付ける。
- 既存メニューを削除しない。
- アドレスバー行の高さが不自然に高くならないようにする。
- 上部の表示/非表示メニューでアドレスバーを非表示にした時の挙動も壊さない。
- WebView2 未初期化時に例外が出ないようにする。
- HelpWindow の既存体裁（ロゴ、目次、区切り線など）を壊さない。
- YouTube / Google / WebView2 関連の本来機能は変更しない。

## 受け入れ条件（目視確認基準）

### ナビゲーションボタン表示確認

1. LiteTube Dock を起動する。
2. MainWindow 上部を見る。
3. アドレスバーの左側に以下4つのボタンが表示されていることを確認する。
   - 戻る
   - 進む
   - 再読み込み
   - ホーム
4. 各ボタンがアイコン表示になっていることを確認する。
5. 一目で意味が分かるデザインであることを確認する。

### ボタン動作確認

1. 適当なYouTubeページをいくつか移動する。
2. 戻るボタンを押す。
3. 1つ前のページへ戻ることを確認する。
4. 進むボタンを押す。
5. 1つ先のページへ進むことを確認する。
6. 再読み込みボタンを押す。
7. 現在ページが再読み込みされることを確認する。
8. ホームボタンを押す。
9. 設定済みのホームURLへ移動することを確認する。

### ボタン有効/無効確認

1. 起動直後など、戻る履歴がない状態で戻るボタンを見る。
2. 戻れない状態が分かることを確認する。
3. 進めない状態で進むボタンを見る。
4. 進めない状態が分かることを確認する。

### ヘルプ確認

1. ヘルプ画面を開く。
2. 「基本操作」付近に以下の説明があることを確認する。
   - 戻るボタンと `Alt + ←`
   - 進むボタンと `Alt + →`
   - 再読み込みボタンと `F5`
   - ホームボタン
3. 既存のヘルプ構成が崩れていないことを確認する。

### 既存機能確認

- ファイルメニュー、表示メニュー、設定メニュー、ヘルプメニューが開ける。
- アドレスバーの URL入力・貼り付け・移動が動作する。
- 現在URLコピーが動作する。
- お気に入りボタンが動作する。
- 下部のお気に入りボタン表示が壊れていない。
- 設定画面、ヘルプ画面、バージョン情報画面を開ける。
- YouTube / Google / WebView2 関連の挙動に変更が入っていない。

## 補足

このチケットでは、まず常設のナビゲーションボタンを追加することが目的である。

アイコンデザイン自体は別途用意してよいが、少なくとも以下が一目で分かることを優先する。

- 戻る
- 進む
- 再読み込み
- ホーム

必要に応じて、将来的にホバー時の見た目や無効時の薄表示などを追加してもよい。
