# 共通前提（必ず遵守）

- AGENT.md が存在する場合、その内容を最優先で遵守させること
- ユーザーはコードを直接編集しない前提である
- 実装・修正はすべて CODEX が行う
- 既存設計を破壊しない
- 既存テーマ・ライブラリ構成を維持する
- ハードコード文字列は禁止
- ICommand構造を崩さない

# タスク名

LiteTubeDock内から最新診断ログを閲覧・選択・コピーできるログ専用ウィンドウ追加

# 目的

LiteTubeDock本体のメニューから、現在出力されている最新の診断ログを専用ウィンドウで閲覧できるようにする。

ログ本文は読み取り専用で表示し、マウスドラッグによる範囲選択、右クリックコピー、`Ctrl+C`、`Ctrl+A`による全文選択、全文コピーに対応する。

また、ログファイルの再読み込み、全文コピー、ログフォルダーを開く操作を用意し、IPCや`MEDIA_NOT_FOUND`等の不具合調査をアプリ内で完結しやすくする。

# 実装内容（具体的変更指示）

1. LiteTubeDockの「ファイル」メニューへ、以下の項目を追加すること。

   ```text
   ログを表示
   ```

2. 可能であれば同じ「ファイル」メニューへ、以下も追加すること。

   ```text
   ログフォルダーを開く
   ```

3. 「ログを表示」を押すと、独立したログ専用ウィンドウを表示すること。

4. ログ専用ウィンドウはメインウィンドウとは別の通常ウィンドウとすること。

5. ログ専用ウィンドウを開いている間も、LiteTubeDock本体を操作できること。

6. ログ専用ウィンドウを複数重複して開かないこと。

7. すでに開いている場合は、新規作成せず既存ウィンドウを前面へ表示すること。

8. LiteTubeDock本体終了時は、ログ専用ウィンドウも終了すること。

9. ログ専用ウィンドウ起動時に、既存ログ保存先から最新のログファイルを自動選択すること。

10. 最新ログファイルの選択は、少なくとも以下を考慮すること。

   - ファイル名の日付
   - 最終更新日時
   - 当日ログが存在する場合は当日ログを優先

11. 現在のログ命名規則に従うこと。

   例:

   ```text
   litetubedock_yyyyMMdd.log
   ```

12. ログファイルが存在しない場合は、異常終了させず以下の趣旨を表示すること。

   ```text
   表示できるログファイルがありません。
   ```

13. ログ本文は読み取り専用で表示すること。

14. ログ本文表示は、以下の操作に対応すること。

   - マウスドラッグによる範囲選択
   - `Ctrl+C`
   - `Ctrl+A`
   - `Ctrl+A`後の`Ctrl+C`
   - 右クリックメニューの「コピー」
   - 縦スクロール
   - 横スクロール

15. ログ本文には等幅フォントを使用すること。

16. ログ本文は改行・空白・記号を保持して表示すること。

17. 長いログ行を折り返すか横スクロールにするかは既存UIとの整合を見て選定してよいが、診断用途では横スクロールを優先すること。

18. ログ専用ウィンドウ上部または下部へ、以下の操作ボタンを追加すること。

   - 再読み込み
   - 全文コピー
   - ログフォルダーを開く
   - 閉じる

19. 「再読み込み」を押すと、現在選択中のログファイルを再読込すること。

20. 最新ログファイルが切り替わっている場合は、再読み込み時に最新ファイルへ追従すること。

21. 「全文コピー」を押すと、現在表示中のログ全文をクリップボードへコピーすること。

22. 全文コピー成功時は、以下の趣旨の通知を表示すること。

   ```text
   ログ全文をコピーしました。
   ```

23. ログが空の場合はコピーせず、以下の趣旨を表示すること。

   ```text
   コピーできるログがありません。
   ```

24. クリップボード操作に失敗しても、アプリを異常終了させないこと。

25. 「ログフォルダーを開く」を押すと、既存ログ保存先をエクスプローラーで開くこと。

26. ログフォルダーが存在しない場合は、自動作成するか、分かりやすいエラーを表示すること。

27. ログ専用ウィンドウ内に、現在表示中のログファイル名を表示すること。

28. 可能であれば、以下も表示すること。

   - フルパスまたはログフォルダー
   - 最終更新日時
   - ファイルサイズ

29. 自動更新機能を追加すること。

30. 自動更新はチェックボックスでON/OFFできること。

   例:

   ```text
   自動更新
   ```

31. 自動更新の初期値はONまたはOFFのどちらでもよいが、既存方針に合わせて統一すること。

32. 自動更新間隔は1秒前後を目安とし、過剰なファイル読み込みを避けること。

33. ファイル最終更新日時またはサイズが変化した場合だけ再読込すること。

34. 自動更新時に毎回ログ本文全体を不必要に再生成しないよう配慮すること。

35. 自動更新中にユーザーがログ本文を選択している場合は、選択範囲を不用意に解除しないこと。

36. ユーザーが途中のログを読んでいる場合、勝手に最下部へスクロールしないこと。

37. 以下のチェックボックスを追加してよい。

   ```text
   更新時に最下部へ移動
   ```

38. 「更新時に最下部へ移動」がONの場合のみ、更新後に末尾へスクロールすること。

39. ログ本文を選択中の場合は、自動スクロールを抑止することを推奨する。

40. ログ専用ウィンドウへ検索機能を追加すること。

41. 検索欄では、少なくとも以下を検索できること。

   - PID
   - Pipe名
   - Command
   - ErrorCode
   - `MEDIA_NOT_FOUND`
   - 任意文字列

42. 検索結果へ移動できる「次を検索」操作を追加すること。

43. `Ctrl+F`で検索欄へフォーカスできることを推奨する。

44. 検索機能の実装が大きくなる場合でも、少なくとも文字列検索と次候補移動までを実装すること。

45. ログ読み込みはUIスレッドを長時間ブロックしないこと。

46. ログファイルが大きい場合でも、アプリが固まらないよう非同期読み込みを検討すること。

47. 必要に応じて、最大表示行数または最大ファイルサイズの制限を設けてよい。

48. 制限を設ける場合は、末尾側の最新ログを優先して表示すること。

49. 制限により省略した場合は、以下の趣旨を表示すること。

   ```text
   ログが大きいため、最新部分のみ表示しています。
   ```

50. ログ表示機能は読み取り専用とし、ログファイルを編集・削除・上書きしないこと。

51. ログウィンドウからログファイルを保存し直す機能は本チケットでは不要とすること。

52. 既存の診断ログ形式、保存先、ローテーション、セキュリティ方針を変更しないこと。

53. ログにCookie、認証情報、トークン、ページ本文等を追加記録しないこと。

54. 既存のURLマスク方針を維持すること。

55. 表示文言、メニュー名、ツールチップ、結果メッセージは既存のリソース管理方式に従い、ハードコードしないこと。

56. 既存のメニュー、WebView2、IPC、アドレスバー、ナビゲーション、設定、About画面を壊さないこと。

57. 実装後、Debug構成でビルドし、警告0・エラー0を確認すること。

# 受け入れ条件（目視確認基準）

## メニュー表示

1. テスターがLiteTubeDockを起動する。
2. 「ファイル」メニューを開く。
3. 「ログを表示」が表示されることを確認する。
4. 「ログフォルダーを開く」を追加した場合、その項目も表示されることを確認する。

## ログ専用ウィンドウ

1. 「ログを表示」を押す。
2. 独立したログ専用ウィンドウが開くことを確認する。
3. LiteTubeDock本体も引き続き操作できることを確認する。
4. 再度「ログを表示」を押す。
5. ログウィンドウが重複して増えず、既存ウィンドウが前面へ出ることを確認する。

## 最新ログ表示

1. ログ専用ウィンドウを開く。
2. 最新の `litetubedock_yyyyMMdd.log` が自動表示されることを確認する。
3. 表示中ファイル名が画面上で確認できることを確認する。
4. ログ本文に改行・空白・記号が維持されていることを確認する。
5. 等幅フォントで表示されることを確認する。

## 範囲選択とコピー

1. マウスドラッグでログ本文の一部を選択する。
2. `Ctrl+C`でコピーする。
3. メモ帳へ貼り付け、選択範囲だけが貼り付けられることを確認する。
4. 右クリックメニューの「コピー」でも同じ動作になることを確認する。

## 全文選択・全文コピー

1. ログ本文へフォーカスする。
2. `Ctrl+A`を押す。
3. 全文が選択されることを確認する。
4. `Ctrl+C`でコピーする。
5. メモ帳へ貼り付け、全文がコピーされていることを確認する。
6. 「全文コピー」ボタンでも同じ内容がコピーされることを確認する。

## 再読み込み

1. ログウィンドウを開いたまま、LiteTubeDockControlから再生・ミュート等を実行する。
2. プレイヤー側ログへ新しい行が追加されることを確認する。
3. 「再読み込み」を押す。
4. 新しいログ行が表示されることを確認する。

## 自動更新

1. 「自動更新」をONにする。
2. LiteTubeDockControlからIPC操作を実行する。
3. 数秒以内に新しいログ行が表示されることを確認する。
4. 自動更新をOFFにする。
5. 新しいログが追加されても、手動再読み込みまで画面更新されないことを確認する。

## スクロール制御

1. ログ本文の途中へスクロールする。
2. 自動更新を発生させる。
3. 「更新時に最下部へ移動」がOFFの場合、勝手に末尾へ移動しないことを確認する。
4. ONの場合は、更新後に末尾へ移動することを確認する。
5. 文字列選択中に自動更新が発生しても、選択操作が極端に妨げられないことを確認する。

## 検索

1. 検索欄へ `MEDIA_NOT_FOUND` と入力する。
2. 「次を検索」を押す。
3. 該当箇所へ移動または選択されることを確認する。
4. PID、Pipe名、Commandでも検索できることを確認する。
5. 該当なしの場合、分かりやすいメッセージが表示されることを確認する。

## ログフォルダー

1. 「ログフォルダーを開く」を押す。
2. エクスプローラーでログ保存先が開くことを確認する。
3. 最新ログファイルが存在することを確認する。

## ログなし

1. ログファイルが存在しない状態を用意する。
2. 「ログを表示」を押す。
3. アプリが異常終了しないことを確認する。
4. 「表示できるログファイルがありません」という趣旨の表示になることを確認する。

## 大容量ログ

1. 大きなログファイルを用意できる場合、ログウィンドウを開く。
2. UIが長時間固まらないことを確認する。
3. 表示制限を設けた場合、最新部分が表示されることを確認する。
4. 省略表示の説明が確認できることを確認する。

## ウィンドウ終了

1. ログウィンドウだけを閉じる。
2. LiteTubeDock本体が残ることを確認する。
3. 再度ログウィンドウを開けることを確認する。
4. LiteTubeDock本体を終了する。
5. ログウィンドウも終了することを確認する。

## 回帰確認

- WebView2表示が動作すること
- アドレスバーとナビゲーションが動作すること
- IPCの`ping`、`get-status`、`navigate`、メディア操作が動作すること
- 設定画面が動作すること
- About画面が動作すること
- 既存ログ出力が従来どおり継続すること
- Debug構成で警告0・エラー0でビルド成功すること
