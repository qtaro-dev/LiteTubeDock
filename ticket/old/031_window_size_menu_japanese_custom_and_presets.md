# チケット031: ウィンドウサイズメニューの表示名修正とプリセット追加・区切り整理

## 目的

MainWindow の `表示` → `ウィンドウサイズ` メニューについて、表示名とプリセット一覧を整理する。

現在、メニュー内の `Custom` が英語表記のままになっており、他のUIが日本語中心のため違和感がある。

また、ウィンドウサイズプリセットに `1024x768` と `768x1024` がないため、使いやすい標準サイズとして追加したい。

あわせて、横画面用プリセットと縦画面用プリセットを分け、水平線で区切って見やすくする。

## 前提

- 作業対象は `E:\Dev\LiteTubeDock` 配下のみとする。
- `E:\Dev\backup_LiteTubeDock` は編集しない。
- AGENT.md が存在する場合は、その内容を最優先で確認・遵守する。
- 既存設計、既存テーマ、既存ライブラリ構成を壊さない。
- 既存 `x:Name` は原則維持する。
- チケット029/030で修正したカスタムサイズ保持・表示メニューと設定画面の同期仕様を壊さない。
- 今回はウィンドウサイズプリセットの表示名・項目追加・メニュー整理のみを対象とする。
- YouTube / Google のログイン、認証情報、広告、DOM操作、WebView2まわりの処理仕様には触れない。
- YouTube広告を自動キャンセル、非表示、削除、置換、スキップする機能は実装しない。
- DOM操作、自動クリック、YouTube内部API呼び出しは行わない。

## 対象ファイル

推定対象:

- `Constants/AppConstants.cs`
- `MainWindow.xaml`
- `MainWindow.xaml.cs`
- `Views/GeneralSettingsView.xaml`
- `Views/GeneralSettingsView.xaml.cs`
- `SettingsWindow.xaml.cs`
- 必要に応じてウィンドウサイズプリセット関連のモデル・サービス

## 現状の課題

### 課題1: 表示メニューの `Custom` が英語表記のまま

`表示` → `ウィンドウサイズ` メニュー内で、カスタムサイズを示す項目が `Custom` と表示されている。

他のUIは日本語表記が多いため、ここだけ英語だと違和感がある。

期待表示:

```text
カスタム
```

### 課題2: 1024x768 / 768x1024 がない

現在のプリセットには以下がある。

```text
800x600
960x540
1280x720
1600x900
1920x1080
540x960
720x1280
900x1600
1080x1920
Custom
```

ここに以下を追加したい。

```text
1024x768
768x1024
```

### 課題3: 横画面用・縦画面用が混ざっていて見づらい

現在は横長サイズと縦長サイズが連続して並んでいる。

横画面用と縦画面用を水平線で区切り、見やすくしたい。

## 実装内容

### 1. 表示メニューの `Custom` を `カスタム` に変更する

`表示` → `ウィンドウサイズ` メニューに表示される `Custom` を `カスタム` に変更する。

重要:

- 画面表示は `カスタム`
- 内部値・保存値は既存仕様を優先する
- 既存の設定ファイル互換性を壊さない

推奨:

```text
内部値: Custom
表示名: カスタム
```

もし現在 `CustomWindowSizePreset` が内部値と表示名を兼ねている場合は、表示名だけを日本語化できるように分離する。

例:

```csharp
public const string CustomWindowSizePreset = "Custom";
public const string CustomWindowSizePresetLabel = "カスタム";
```

のように、保存・判定用と表示用を分ける。

既存設定ファイルに `Custom` が保存されている場合でも、引き続き正しく読み込めること。

### 2. 1024x768 プリセットを追加する

横画面用プリセットに以下を追加する。

```text
1024x768
```

要件:

- 表示メニューに表示されること。
- 設定画面のウィンドウサイズプリセットにも表示されること。
- 選択時に MainWindow が `1024 x 768` へリサイズされること。
- 設定保存後、再起動しても `1024 x 768` として復元されること。
- 表示メニューと設定画面の同期仕様を維持すること。

### 3. 768x1024 プリセットを追加する

縦画面用プリセットに以下を追加する。

```text
768x1024
```

要件:

- 表示メニューに表示されること。
- 設定画面のウィンドウサイズプリセットにも表示されること。
- 選択時に MainWindow が `768 x 1024` へリサイズされること。
- 設定保存後、再起動しても `768 x 1024` として復元されること。
- 表示メニューと設定画面の同期仕様を維持すること。

### 4. 表示メニュー内で横画面用・縦画面用を水平線で区切る

`表示` → `ウィンドウサイズ` メニュー内を以下のように整理する。

希望表示例:

```text
800x600
960x540
1024x768
1280x720
1600x900
1920x1080
----------------
540x960
720x1280
768x1024
900x1600
1080x1920
----------------
カスタム
```

要件:

- 横画面用プリセットと縦画面用プリセットの間に水平線を入れる。
- 縦画面用プリセットとカスタムの間にも水平線を入れる。
- WPFの `Separator` など、自然なメニュー区切りを使用する。
- 区切り線自体は選択不可であること。
- チェック状態はプリセット項目またはカスタム項目にのみ付くこと。

### 5. 設定画面側のプリセット一覧にも追加する

設定画面の基本設定にあるウィンドウサイズプリセット一覧にも、以下を追加する。

```text
1024x768
768x1024
```

要件:

- 設定画面のコンボボックス等にも表示されること。
- 表示メニューと同じ設定値として扱うこと。
- 設定画面で `1024x768` を選んで保存すると、表示メニュー側にも反映されること。
- 設定画面で `768x1024` を選んで保存すると、表示メニュー側にも反映されること。
- `Custom` ではなく `カスタム` と表示されること。
- 内部値・保存値の互換性を壊さないこと。

### 6. チケット029/030の仕様を維持する

以下の仕様を壊さない。

- カスタムサイズをプリセットへ勝手に丸めない。
- `420x451 → 540x451` のような置き換えをしない。
- 「現在のウィンドウサイズを取得」で取得した値をそのまま保存・復元する。
- 表示メニューと設定画面のウィンドウサイズ設定は同じ保存値を参照する。
- お気に入り設定だけを保存しても MainWindow のサイズを変更しない。
- キャンセル、右上 `×` で設定画面を閉じた場合はサイズ設定を変更しない。

## 実装時の注意

- `Custom` を直接 `カスタム` に置き換えるだけで、保存値や判定が壊れないか確認する。
- 既存設定ファイルに `Custom` が入っていても読み込めるようにする。
- 表示名だけ日本語化するのが安全。
- 1024x768 / 768x1024 を追加する場合、定数追加だけでなく、メニュー生成処理・設定画面のリスト・サイズ適用処理にも反映する。
- 表示メニューの `Separator` にチェック状態が付かないようにする。
- プリセット一覧の順序を分かりやすく保つ。
- YouTube / Google / WebView2 関連の処理には触れない。

## 受け入れ条件（目視確認基準）

### TC-01: 表示メニューの Custom がカスタムになっている

1. LiteTube Dock を起動する。
2. `表示` → `ウィンドウサイズ` を開く。
3. 一番下の `Custom` が `カスタム` と表示されていることを確認する。
4. `Custom` という英語表記が残っていないことを確認する。

### TC-02: 表示メニューに 1024x768 が追加されている

1. `表示` → `ウィンドウサイズ` を開く。
2. 横画面用プリセットの中に `1024x768` が表示されていることを確認する。
3. `1024x768` を選択する。
4. MainWindow が `1024 x 768` にリサイズされることを確認する。

### TC-03: 表示メニューに 768x1024 が追加されている

1. `表示` → `ウィンドウサイズ` を開く。
2. 縦画面用プリセットの中に `768x1024` が表示されていることを確認する。
3. `768x1024` を選択する。
4. MainWindow が `768 x 1024` にリサイズされることを確認する。

### TC-04: 横画面用・縦画面用・カスタムが水平線で区切られている

1. `表示` → `ウィンドウサイズ` を開く。
2. 横画面用プリセットの後に水平線があることを確認する。
3. 縦画面用プリセットの後に水平線があることを確認する。
4. `カスタム` が最後に表示されることを確認する。
5. 水平線は選択できないことを確認する。

### TC-05: 設定画面にも 1024x768 / 768x1024 が表示される

1. 設定画面を開く。
2. 基本設定のウィンドウサイズプリセット一覧を開く。
3. `1024x768` が表示されることを確認する。
4. `768x1024` が表示されることを確認する。
5. `Custom` ではなく `カスタム` と表示されることを確認する。

### TC-06: 設定画面から 1024x768 を保存できる

1. 設定画面を開く。
2. ウィンドウサイズプリセットで `1024x768` を選択する。
3. 「保存」を押す。
4. MainWindow が `1024 x 768` になることを確認する。
5. `表示` → `ウィンドウサイズ` を開く。
6. `1024x768` が現在のサイズ設定として扱われていることを確認する。

### TC-07: 設定画面から 768x1024 を保存できる

1. 設定画面を開く。
2. ウィンドウサイズプリセットで `768x1024` を選択する。
3. 「保存」を押す。
4. MainWindow が `768 x 1024` になることを確認する。
5. `表示` → `ウィンドウサイズ` を開く。
6. `768x1024` が現在のサイズ設定として扱われていることを確認する。

### TC-08: カスタムサイズ保持が壊れていない

1. MainWindow を手動で `420 x 451` 付近に調整する。
2. 設定画面を開く。
3. 「現在のウィンドウサイズを取得」を押す。
4. カスタムサイズとして保存する。
5. 保存後、MainWindow が `540 x 451` などに勝手に置き換わらないことを確認する。
6. `表示` → `ウィンドウサイズ` を開く。
7. `カスタム` が現在のサイズ設定として扱われていることを確認する。

### TC-09: 既存設定ファイル互換確認

1. 既存の `settings.json` に `Custom` が保存されている状態でもアプリを起動する。
2. 起動時にエラーが出ないことを確認する。
3. 表示上は `カスタム` と表示されることを確認する。
4. カスタムサイズが維持されることを確認する。

## 既存機能確認

- MainWindow が通常通り起動する。
- アドレスバーの URL入力・貼り付け・移動が動作する。
- 戻る、進む、再読み込み、ホームボタンが動作する。
- お気に入りボタンが動作する。
- 設定画面を開閉できる。
- ヘルプ画面、バージョン情報画面を開ける。
- 表示メニューの他項目が動作する。
- チケット029/030のカスタムサイズ保持・同期仕様が壊れていない。
- YouTube / Google / WebView2 関連の処理に変更が入っていない。

## 補足

今回の主目的は、表示名の違和感解消と、よく使う標準サイズの追加である。

特に `Custom` は、内部値としては英語のままでもよいが、画面上は `カスタム` と表示する。

内部値と表示名を分けることで、既存設定ファイルとの互換性を維持しつつ、日本語UIとして自然にする。
