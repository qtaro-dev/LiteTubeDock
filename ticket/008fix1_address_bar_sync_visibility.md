# タスク名

チケット008fix1 アドレスバーURL同期と表示切り替え追加

# 目的

チケット008でMainWindowにアドレスバーを追加したが、現在はアドレスバーからWebView2へURL遷移する機能が中心で、WebView2側で現在表示・再生しているYouTubeページのURLがアドレスバーへ十分に同期されていない。

また、常時表示されるアドレスバーは、動画視聴や小窓運用では邪魔になる場合がある。

そのため、以下を実装する。

- WebView2で現在表示中のURLをアドレスバーへ同期する
- YouTube内で動画・ライブ・チャンネル等へ移動した場合もアドレスバーへ反映する
- Home / Back / Forward / Reload / お気に入りボタン / アドレスバー遷移のすべてでアドレスバーを現在URLに追従させる
- 表示メニューからアドレスバーの表示・非表示を切り替えられるようにする
- アドレスバー表示状態を設定として保存・復元する

# 実装内容（具体的変更指示）

## 1. 作業開始前の確認

- 必ず `AGENT.md` を読むこと。
- 作業対象は `E:\Dev\LiteTubeDock` 配下のみとすること。
- `E:\Dev\LiteTubeDock` の外側にあるファイルやフォルダは一切編集しないこと。
- 既存UIの `x:Name` は原則変更しないこと。
- 既存のWebView2表示、メニュー、お気に入りボタン、ステータスバーを壊さないこと。

## 2. WebView2現在URLとアドレスバーを同期する

WebView2で現在表示中のURLが変わった時、`AddressTextBox` に現在URLを反映する。

対象となる遷移例:

- アドレスバーからURL入力して移動
- Homeメニュー
- Backメニュー
- Forwardメニュー
- Reloadメニュー
- お気に入りボタン
- YouTube内で動画をクリック
- YouTube内でライブページへ移動
- YouTube内でチャンネルページへ移動
- YouTubeのSPA的な画面内遷移

実装候補:

- `PlayerWebView.NavigationCompleted`
- `PlayerWebView.SourceChanged`
- `PlayerWebView.CoreWebView2.SourceChanged`

YouTubeでは通常のページ遷移とは異なる画面内遷移があるため、可能であれば `CoreWebView2.SourceChanged` を利用して同期すること。

## 3. AddressTextBox更新方針

`AddressTextBox` は、現在WebView2で表示中のURLを示す欄として扱う。

仕様:

- WebView2の現在URLが変わったら、`AddressTextBox` を更新する
- `CurrentUrlText` と矛盾しない内容にする
- URLが取得できない場合は空文字にせず、既存表示を維持するか、安全な既定値にする
- 更新時にアプリがクラッシュしないこと

## 4. 入力中の上書き防止

ユーザーが `AddressTextBox` に手入力している最中に、WebView2側のURL変更で入力内容が勝手に上書きされると使いにくい。

そのため、以下の方針で実装する。

- `AddressTextBox` にキーボードフォーカスがあり、ユーザーが入力中の場合は、原則として即時上書きしない
- `NavigateButton` 押下または Enter による移動後は、移動先URLへ同期する
- `AddressTextBox` からフォーカスが外れた時、必要に応じて現在URLへ同期してよい

実装が複雑になる場合は、最低限以下を満たすこと。

- YouTube内で動画へ移動した後、アドレスバーが現在動画URLになる
- Home / Back / Forward / お気に入りボタン後、アドレスバーが現在URLになる
- 入力操作中に極端に使いにくい上書きが発生しない

## 5. 表示メニューにアドレスバー表示切り替えを追加する

`MainWindow.xaml` の `ViewMenuItem` 配下に、アドレスバー表示・非表示を切り替えるメニュー項目を追加する。

推奨表示名:

```text
アドレスバーを表示
```

推奨 `x:Name`:

```text
ShowAddressBarMenuItem
```

仕様:

- チェック付きメニュー項目にする
- チェックON: アドレスバー表示
- チェックOFF: アドレスバー非表示
- クリックするたびに表示・非表示を切り替える
- 表示状態とメニューのチェック状態を同期する

## 6. アドレスバー非表示時のレイアウト

アドレスバー非表示時は、WebView2表示領域がその分広がるようにする。

仕様:

- `AddressBarPanel.Visibility = Collapsed` を基本とする
- 余白だけ残らないようにする
- WebView2表示領域、お気に入りボタン列、ステータスバーのレイアウトが大きく崩れないこと

## 7. 表示状態の保存

アドレスバーの表示・非表示状態を `settings.json` に保存する。

推奨項目:

```json
{
  "showAddressBar": true
}
```

既定値:

```text
true
```

仕様:

- 初回起動時はアドレスバーを表示する
- 表示メニューで非表示にした状態で終了した場合、次回起動時も非表示にする
- 表示メニューで表示に戻した場合、次回起動時も表示する

## 8. フルスクリーンとの整合性

既存仕様では、フルスクリーン中は操作UIを非表示にする。

この仕様を維持する。

- フルスクリーン中はアドレスバーを非表示にする
- フルスクリーン解除後は、`showAddressBar` 設定に従って表示・非表示を復元する
- フルスクリーン前にアドレスバー非表示だった場合、解除後も非表示のままにする
- フルスクリーン前にアドレスバー表示だった場合、解除後は表示する

## 9. 現在URLコピーとの整合性

`CopyCurrentUrlButton` は、アドレスバー表示中のみ押せる。

ただし、アドレスバー非表示中でも内部的な現在URL取得は壊さないこと。

将来的にメニューから現在URLコピーを追加する可能性があるため、現在URL取得処理は可能なら共通化すること。

## 10. README更新

READMEに以下を追記する。

- アドレスバーは現在表示中のWebView2 URLへ同期されること
- YouTube内で動画やライブへ移動した場合も、アドレスバーへ現在URLが反映されること
- 表示メニューからアドレスバーを表示・非表示できること
- アドレスバー表示状態は `settings.json` の `showAddressBar` に保存されること
- フルスクリーン中はアドレスバーが非表示になり、解除後は設定状態に戻ること

## 11. 実装しないこと

今回のタスクでは以下を実装しない。

- アドレスバーからの検索キーワード検索
- YouTube検索専用欄
- 現在URLをお気に入りへ登録する機能
- URL履歴機能
- タブ機能
- 複数ウィンドウ機能
- YouTube UI改変
- Googleログイン自動化

- Forwardを押すと、アドレスバーが進んだ先のURLへ更新される

## 入力中の確認

- アドレスバーに手入力中、極端に勝手な上書きが発生しない
- Enterまたは移動ボタンで遷移後、現在URLへ同期される

## 表示切り替え確認

- `表示` メニュー配下に `アドレスバーを表示` がある
- メニュー項目にチェック状態が表示される

- アドレスバーを非表示にしてアプリを終了する
- 再起動後もアドレスバーが非表示で起動する
- アドレスバーを表示に戻してアプリを終了する
- 再起動後もアドレスバーが表示される
- `settings.json` に `showAddressBar` が保存される

## フルスクリーン確認

- アドレスバー表示状態でフルスクリーンにすると、アドレスバーが非表示になる
- フルスクリーン解除後、アドレスバーが表示に戻る
- アドレスバー非表示状態でフルスクリーンにすると、解除後も非表示のままになる

## 既存機能確認

- Home / Back / Forward / Reload が動作する
- お気に入りボタンでURL遷移できる
- お気に入りボタンの色・アイコン表示が壊れていない
- 現在URLコピーが壊れていない
